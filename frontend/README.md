# 공시체크 프론트엔드

Vue 3 + TypeScript + Vite + Vue Router + Pinia 기반 로컬 UI입니다. **실제 Agent·업무 API·MCP·DB를 호출하지 않습니다.** 엘앤에프·삼성중공업의 공개 사건을 바탕으로 한 고정된 시연 데이터와 가상의 사내 메모를 사용합니다. 실제 투자 분석·증권사 보고서·서버 저장 결과가 아닙니다.

## 실행

Node.js 22.18 이상(22 계열) 또는 24.12 이상, npm을 사용합니다. 저장소 루트에서:

```bash
cd frontend
npm ci
npm run dev
```

접속 주소: http://127.0.0.1:5173 (고정 포트). 백엔드·Docker·API 키가 필요하지 않습니다. 개발 서버는 loopback에만 바인딩됩니다.

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

빌드 결과는 `dist/`에 생성됩니다. 정적 호스팅 시 `/companies/...`, `/analyses/...` 경로를 `index.html`로 보내는 SPA fallback이 필요합니다.

## 화면과 시연

기업 목록은 기존 엘앤에프·삼성중공업에 삼성전자·SK하이닉스·현대차·기아·LG에너지솔루션·삼성바이오로직스·NAVER·KB금융·LG화학·한화에어로스페이스를 추가한 12개 샘플로 구성합니다. 기업명·보통주 코드는 실제 기업을 사용하며, 새 기업의 공시·메모·보고서는 초기 0건입니다. 관심종목과 상세 페이지의 빈 상태를 시연하며 실제 자료가 수집됐다고 표시하지 않습니다. 분석 시나리오는 기존 두 사례만 제공합니다.

홈의 미확인 업데이트는 관심종목 행의 공시·AI 보고서 배지로 표시합니다. 각 배지는 미확인 수가 1 이상일 때만 나타나고 해당 문서를 열람하면 개별적으로 사라집니다. 별도 관심종목 업데이트 목록은 제공하지 않습니다.

`/`는 `/home`으로 이동합니다. 상단 **홈 / 기업 목록**으로 개인 홈과 전체 목록을 오갑니다. `/login`은 데모 사용자를 선택하는 시연 화면이며 실제 인증·권한 검사를 하지 않습니다. 선택 후 홈으로 이동합니다. 처음에는 이차전지 담당 데모 사용자를 표시하며 홈에서 조선 담당 사용자로 전환할 수 있습니다.

홈의 시세 스트립은 국내·해외 지수, 환율·금리, 원자재 12개 지표를 카테고리 필터와 가로 스크롤로 표시합니다. 스크롤바·이동 버튼은 숨기고 지표 위에서 마우스 휠·트랙패드로 이동합니다. 모바일 터치와 키보드 이동은 유지합니다. KOSPI·KOSDAQ·KOSPI 200·S&P 500·NASDAQ·NIKKEI 225·USD/KRW·DXY·미국채 10Y·WTI·GOLD·COPPER 값은 모두 **고정 예시값**이며 실시간 시세나 실제 특정일 종가가 아닙니다. 미국채 10Y 변동은 bp 단위로 표시합니다. 관심종목은 기업 목록의 별 버튼으로 추가·해제하며 데모 사용자 ID별로 분리해 브라우저 `disclosure-check.preferences.v1`에 저장합니다. 빈 관심종목 목록과 마지막 선택 사용자도 유지합니다. 담당 분야·종목은 두 데모 프로필에 고정된 샘플입니다. 이 기능은 로그인한 서버 사용자나 실제 접근 권한을 대체하지 않습니다. 문서·읽음 기록은 기존 공유 데모 흐름을 유지합니다.

1. `/companies`: 기업 배너의 공시·메모·AI 보고서 미확인 건수를 확인합니다. 배너는 기업 상세로, 배지는 해당 탭으로 이동합니다.
2. `/companies/lnf` 또는 `/companies/shi`: 공시를 열람하고 대상 공시·메모·기준 버전을 선택한 다음 분석을 시작합니다.
3. `/analyses/:taskId`: 7개 단계와 선택 관점을 거쳐 시연 보고서가 생성·저장됩니다. 임의 백분율은 사용하지 않습니다.
4. 기존 문장의 ‘원문 문맥 확인’은 **고정된 메모 버전의 해당 문단**을 강조합니다. 근거 자료는 출처·시점·위치를 표시하고 외부 원문을 연결합니다.
5. `/companies/:companyId?tab=memos`: 해당 종목의 메모를 검색·열람하고 UTF-8 `.txt` 파일(최대 5 MiB)을 추가합니다. 업로드는 현재 종목에 연결되는 v1이며 원본 수정·삭제·버전 추가 API를 가정하지 않습니다. 이 기업 연결은 프론트엔드 샘플 동작으로, 실제 업로드 API의 기업 지정 기능을 의미하지 않습니다.
6. `/companies/:companyId?tab=history`: 해당 종목의 완료·근거 부족·진행 중·실패·저장 실패 작업을 상태별로 확인합니다. 상단에는 홈·기업 목록을 두고 메모·이력은 종목 상세에서 관리합니다. 기존 `/memos`, `/analyses`는 기업 목록으로 이동합니다. `/analyses/sample-save-failed`는 생성된 내용을 유지한 채 저장만 재시도합니다.

승인·원본 자동 수정·PDF 처리·실제 로그인은 포함하지 않습니다. 문서 본문은 HTML로 실행하지 않고 텍스트로 렌더링합니다.

### 데이터 수명과 읽음

- 읽음은 `demo-ra` 사용자·문서 종류·ID·버전별로 브라우저 localStorage에 저장합니다. 기업·탭 진입만으로 읽음 처리하지 않습니다.
- 업로드한 파일 본문·신규 작업·생성 보고서는 **현재 실행의 메모리 안에만** 있습니다. 새로고침하면 초기 샘플로 돌아가며 읽음 기록만 남습니다. 사내 본문을 localStorage에 저장하지 않습니다.
- 사라진 신규 작업 URL로 진입하면 초기화 안내를 표시합니다.
- 업로드 시각은 실제 메모 작성일을 뜻하지 않습니다. 업로드 메모로 시연하면 작성일·내용의 적합성 미확인과 고정 해석 사용을 경고하고 판정을 보류합니다. 종목 연결은 업로드 본문이 검증됐다는 의미가 아닙니다.

### 사례 범위

- 엘앤에프: 금액 정정과 실제 매출 영향 구분, 기준 메모 버전 고정, 근거 부족 표시. 접수번호 미확인 상태를 그대로 표시합니다. 12월 30일 보도는 배경 참고 링크이며 12월 29일 분석의 근거 목록에는 넣지 않습니다.
- 삼성중공업: 해지 공시 2건의 개별 접수번호, 원래 반영된 손실과 추가 부담의 구분. 공시·메모 본문은 원본이 아닌 **시연용 요약**입니다. 미확인 시각·세부 금액을 실제 확인된 값으로 취급하지 않습니다.
- 샘플 기준일 이전에 작성된 가상 메모를 사용하며, 실제 공시 추출·미래 자료 배제·금융 계산 정확도는 이 UI 테스트로 검증하지 않습니다.

## 구조와 후속 API 연결

```text
src/
├── views/         # 기업·메모·분석 화면
├── components/    # 문서 drawer, 분석 시작, 상태·빈 화면
├── services/      # 비동기 업무 계약, 샘플 구현, 업로드 검증
├── stores/        # 화면 상태·기준 문서·읽음
├── fixtures/      # 두 사례·시연용 메모·보고서
├── types/         # 화면 도메인 타입·상태 표시
├── styles/        # 데스크톱·모바일 스타일
└── lib/           # KST 날짜 표시
```

컴포넌트는 fixture에 직접 접근하지 않습니다. `services/contracts.ts`의 `Services`를 구현한 HTTP adapter를 만들고 `services/index.ts`의 factory를 교체하면 됩니다. 화면 모델은 camelCase, 기존 API DTO는 snake_case이므로 adapter에서 변환합니다. 샘플 ID는 실제 API의 UUID라고 가정하면 안 됩니다.

아래 표는 구현 시작 기준 커밋 **799552f**의 서버 상태입니다. 현재 프론트엔드 브랜치에는 `origin/main`의 **3ded934**까지 반영돼 있으며 분석 생성·조회·SSE·내부 보고서 API가 포함돼 있습니다. 백엔드 코드는 원격 main과 동일하게 유지합니다. 사용자 요청에 따라 실제 API 연결 작업은 중단하고 UI 퍼블리싱만 진행합니다. 후속 연동에서는 최신 서버의 schema와 endpoint를 확인하고 이미 추가된 API를 재사용해야 합니다.

| 영역               | 기준 커밋의 서버                               | 연결할 때 필요한 작업                                                                                |
| ------------------ | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 인증               | `POST /api/v1/auth/login`                      | 로그인 화면·Bearer 세션·401/403 처리. 조직 판정은 서버가 수행                                        |
| 공시               | `GET /api/v1/filings`, 단건·접수번호·버전 조회 | 저장된 캐시만 반환. 부분 검색·실시간 OpenDART 조회 API로 가정하지 않음                               |
| 메모               | `GET/POST /api/v1/memos`, 단건·버전 조회       | `multipart/form-data`의 file·선택 title만 전송. 회사명 null 허용, `versions/{version}`에서 본문 조회 |
| 기업·배지          | 미구현                                         | 기업 식별·목록과 사용자별 문서 버전 읽음·업데이트 집계 계약 필요                                     |
| 분석·보고서·이벤트 | 모델·상태·Repository만 있음                    | 작업 생성/조회, 기준 버전 고정, 보고서 조회, 저장 재시도, 진행 이벤트 API 필요                       |

기존 목록 API는 배열과 limit/offset을 반환하며 total을 제공하지 않습니다. 합계를 클라이언트 페이지 길이로 오인하지 않도록 실제 연동에서 집계 계약을 별도로 정해야 합니다. 서버의 오류 envelope(`error.code/message` 또는 422 `detail`)는 adapter에서 화면 오류로 변환합니다.

### 관점과 상태 계약

화면 관점은 `BUSINESS_INDUSTRY`(기업·산업), `FINANCE`(재무·실적), `EXTERNAL_RISK`(외부 환경·위험)입니다. 서버의 `FX_HEDGE`, `INDUSTRY_CONTRACT`와 **의미가 달라 라벨만 바꿔 연결하면 안 됩니다.** 실제 연동 전에 서버 enum·마이그레이션·Agent 역할 정렬이 필요합니다. 이번 작업은 백엔드를 변경하지 않습니다.

작업 상태·단계·영향 판정은 기존 서버 enum과 동일합니다. 추가로:

- 입력은 공시 한 건, 메모와 기준 버전을 고정합니다. 관련 공시 2건을 분석 요청에 자동 합산하지 않습니다.
- 선택하지 않은 관점은 실행하지 않고 사유를 표시합니다.
- 근거 부족·조회 한도·분석 실패·저장 실패를 구분합니다.
- `savedAt === null`은 미저장입니다. 저장 실패 시 생성 내용을 유지하고 저장만 재시도합니다.
- 실제 이벤트 adapter는 순서·재연결·인증을 처리해야 합니다. 샘플은 sequence가 증가하는 인메모리 구독이며 최신 서버의 SSE에는 아직 연결하지 않았습니다.
- 메모/공시의 접근 권한과 기준일 검증은 실제 연동 시 업무 서버·Agent가 보장해야 하며 프론트엔드 표시만으로 보장되지 않습니다.

## 테스트

```bash
npm test
npx playwright install chromium
npm run test:e2e
```

설치된 Google Chrome으로 검증하려면:

```bash
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```

Playwright는 로컬 서버가 없으면 자동으로 시작하며 1440×1100·390×844에서 검증합니다. 캡처·실패 추적·HTML 보고서는 Git에서 제외된 `test-results/`, `playwright-report/`에 생성합니다.

오류 화면은 별도 제품 메뉴 없이 아래 URL로 재현합니다. 모두 로컬 샘플 기능입니다.

| URL                                        | 시연                                 |
| ------------------------------------------ | ------------------------------------ |
| `/companies?demo=empty`                    | 빈 기업 목록                         |
| `/companies?demo=error`                    | 초기 조회 실패·재시도                |
| `/companies/lnf?scenario=evidence-gap`     | 분석 시작 후 근거 부족               |
| `/companies/lnf?scenario=limit`            | 분석 시작 후 조회 한도 도달          |
| `/companies/lnf?scenario=analysis-failure` | 분석 시작 후 필수 조회 실패          |
| `/companies/lnf?scenario=save-failure`     | 분석 시작 후 저장 실패·저장만 재시도 |

실제 Agent 정확도·금융 해석·서버 E2E·조직별 권한은 검증 범위에 포함하지 않습니다.
