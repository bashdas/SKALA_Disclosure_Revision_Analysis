# 공시체크 프론트엔드

## 1. 개요

Vue 3, TypeScript, Vite, Pinia로 구성한 업무 화면입니다. GitHub main의 기업 목록 표, 홈 관심종목 표와 기업 상세 작업 영역을 유지하며 실제 Business API를 호출합니다.

## 2. 실행 준비

Node.js 22.18 이상인 22 계열 또는 24.12 이상을 사용합니다. Backend와 OpenDART 설정이 필요합니다. 전체 서버 실행 방법은 저장소 루트 README를 따릅니다. API 키는 서버의 `backend/.env`에 보관합니다.

## 3. 실행

```bash
cd frontend
npm ci
npm run dev
```

접속 주소는 `http://127.0.0.1:5173`입니다. `/api` 요청은 기본적으로 `http://127.0.0.1:8080`으로 전달합니다. 다른 서버를 사용할 때는 실행 환경변수 `API_PROXY_TARGET`을 지정합니다.

## 4. 사용 흐름

회원가입 후 로그인합니다. 가입하면 새 조직과 RA 계정이 생성됩니다. 기존 계정은 로그인 폼을 사용합니다. 내 계정 화면에서 비밀번호를 변경하면 기존 세션이 만료됩니다.

기업 목록은 OpenDART의 실제 회사 목록을 검색하고 20건씩 이어서 조회합니다. 기본 정렬은 코스피·코스닥 통합 시가총액 높은 순이며 검색창 옆에서 시가총액 낮은 순·기업명순으로 바꿀 수 있습니다. 시가총액이 없는 기업은 시총 정렬의 마지막에 표시합니다. 시총 자료는 서버에서 5분간 공유하고 추가 페이지는 첫 페이지의 순위 스냅샷을 사용해 중복·누락을 방지합니다. 오래된 스냅샷이 만료되면 다시 시도로 첫 페이지부터 조회합니다. 기업명, 종목코드와 고유번호로 검색할 수 있습니다. 별표를 누르면 사용자 계정에 즐겨찾기를 저장하고 내 페이지의 관심종목 표에 표시합니다.

기업에 들어가면 공시 탭에서 해당 기업의 신규 공시와 정정공시를 확인합니다. 날짜를 지정하지 않으면 전체 기간을 조회합니다. 기간과 공시명·공시번호 검색을 지원하며 다음 페이지는 스크롤로 추가합니다. 14자리 국내 접수번호는 번호의 날짜 부분으로 서버 조회 범위를 좁혀 정확한 번호를 찾고, 선택한 회사·기간 조건을 유지합니다. 열린 기업 화면은 1분마다 목록을 갱신합니다.

공시 목록의 분석하기 버튼을 누르면 기준 메모와 버전을 선택하는 모달이 열립니다. 신규공시와 정정공시 모두 분석할 수 있습니다. 분석 시작 시 공시를 서버에 등록하고 선택한 기존 메모 버전과 비교합니다. 메모 관리에서 기존 메모를 업로드하거나 저장한 뒤 선택합니다. 미등록 또는 등록 해제된 공시는 서버가 REGISTERED_FILING_REQUIRED로 거부합니다. SEC 기업은 `SEC:CIK` 식별자로 관심 기업에 등록하며 8-K와 실적 첨부자료를 조회합니다.

메모 목록의 삭제 버튼으로 메모를 삭제합니다. 기존 분석에서 참조한 원문은 보존합니다. 기업 상세의 AI 보고서 탭에서 진행·완료·실패·취소를 포함한 분석을 한 번씩 표시하고 상태로 필터링합니다. 저장된 결과는 보고서 보기로, 나머지는 분석 확인으로 엽니다. 기존 tab=history 링크도 같은 통합 탭을 표시합니다. 보고서는 공시 영향 분석 보고서라는 상단 제목으로 한 번만 표시하며 본문의 중복 제목은 숨깁니다. 통합 헤더에 저장 시각과 MD·PDF 다운로드를 모으고, 본문의 핵심 요약·공시 변경 내용, 관점별 분석 결과, 향후 영향과 조건, 메모수정 제안 비교 카드, 확인 범위와 남은 질문을 이어서 표시합니다. 완료된 분석은 진행 기록을 숨기며 진행 중·실패 상태에는 유지합니다. 완료 보고서에서는 선택 관점의 이유·상태 안내를 표시하지 않고 관점별 분석 결과만 유지합니다. 향후 영향과 조건의 예상 영향은 다음 줄에 표시합니다. 연결 근거는 본문과 같은 근거 번호로 표시하고, 출처와 원문 인용 목록은 기본으로 닫힌 토글에서 펼쳐 확인합니다. 선택 이유·분석 결과·메모 수정 제안이 중복되지 않도록 Markdown 제목 구조를 기준으로 대체 가능한 구역만 제외합니다. 대체 데이터가 없거나 알 수 없는 구역은 원문을 유지하고, 본문에 빠진 요약·공시 변경·관점 결과는 기존 구조화된 데이터로 보완합니다. 보고서가 생성되기 전에는 선택 관점을 별도 진행 영역에서 확인합니다. 별도 근거 자료 목록 대신 본문의 [근거 N]에 마우스를 올리거나 키보드로 초점을 맞추면 인용문을 미리 보고, 클릭·Enter·모바일 터치로 상세 패널에서 전체 인용과 원문 링크를 확인합니다. 실제 근거가 없는 번호는 일반 텍스트로 유지합니다. 본문은 Markdown 제목과 표로 렌더링하며 기존 MD·PDF 다운로드 내용과 저장 데이터는 유지합니다.

## 5. 데이터와 접근 범위

Bearer 토큰은 현재 탭의 sessionStorage에 보관합니다. 조직의 메모, 공시와 보고서는 서버에 저장하며 새로고침 후 다시 조회합니다. 즐겨찾기는 사용자별로 저장합니다. 읽음 기록과 테마는 브라우저에 보관합니다.

업로드 메모는 최대 5 MiB입니다. 기업 상세에서 저장하면 선택한 기업의 코드를 서버에서 확인해 메모에 연결합니다. 기업별 메모 목록, 분석 선택란과 읽지 않은 개수는 같은 기업 필터를 사용합니다. 기업 미지정 메모는 기업별 목록에서 제외합니다. 공시 등록 해제는 목록에서 숨기는 처리이며 기존 분석이 참조하는 원문은 보존합니다.

시장 지표 12개 카드는 기존 배치를 유지하며 실제 수치와 전일 대비 변화를 표시합니다. 국내 지수는 네이버 금융, 해외 지수와 환율, 금리 및 원자재는 Yahoo Finance의 최근 한 달 일별 자료를 사용합니다. 장중 일별 자료에는 진행 중인 거래일의 값이 포함될 수 있습니다. 화면과 서버 캐시는 1분마다 갱신하며 실시간 체결 시세를 보장하지 않습니다.

카드에 마우스를 올리면 일별 자료 기준 시각을 한국 시간으로 표시합니다. 미국채 10년 금리는 수익률과 전일 대비 bp를 표시합니다. 원자재는 선물 가격이며 구리는 USD/lb를 USD/t로 환산합니다. 미수신 지표는 미제공으로 표시하며 서버 연결 실패 때는 이전 수신 값이라는 상태를 표시합니다.

이 조회 경로는 별도 키 없이 호출하는 웹 차트 데이터이며 외부 제공자의 제한이나 규격 변경으로 실패할 수 있습니다. 기업 목록과 관심종목 표는 네이버 금융의 KRX 종목 시세를 1분마다 조회합니다. 현재가와 전일 종가로 부호가 있는 등락률을 계산하며 거래대금은 원 단위 누적 거래대금입니다. 시가총액은 현재가와 상장 주식 수의 곱입니다. 한 요청은 최대 50개 종목이며 응답은 1분 단위로 보관합니다. 비상장 또는 제공자 응답에 없는 종목은 시세 없음으로 표시합니다. 갱신 실패 때는 이전 수신 값을 유지하고 오류를 표시합니다.

## 6. API 연결

`src/services/market.ts`는 `GET /api/v1/market/indices`로 시장 지표를 조회합니다. 서버가 고정된 12개 지표만 조회하고 60초 동안 응답을 보관합니다. 이 API는 공개 시장 자료만 반환하며 로그인이나 DB 연결을 요구하지 않습니다.

메모 저장은 multipart의 company_id로 선택 기업을 전달합니다. PATCH /api/v1/memos/{id}/company는 같은 조직의 기존 메모에 확인한 기업을 연결합니다. 기업 변경은 본문과 버전, 원본 해시를 보존합니다.

`src/services/http.ts`에서 인증, 메모, 공시 버전과 분석 응답을 화면 모델로 변환합니다. `src/services/catalog.ts`는 회사 검색, 즐겨찾기와 OpenDART 공시 목록을 호출합니다. 분석 진행은 2초 간격으로 조회하며 서버의 관점 결과와 저장된 보고서를 표시합니다.

브라우저는 `/api/v1`만 호출합니다. 내부 인증키와 MCP 주소는 프론트엔드에 전달하지 않습니다. 원문의 HTML은 실행하지 않습니다. 보고서 Markdown의 HTML과 이미지도 실행하거나 불러오지 않습니다.

## 7. 검증

```bash
npm run typecheck
npm test
npm run build
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e -- --project=desktop
```

실제 서버 흐름은 `E2E_EMAIL`, `E2E_PASSWORD`, `E2E_COMPANY_CODE`, `E2E_COMPANY_NAME`, `E2E_CORRECTION_TITLE`을 지정합니다. 전용 검사 계정을 사용합니다. `E2E_PORT`를 지정하면 별도 테스트 서버를 실행합니다. 캐시와 Playwright 결과는 OS 임시 폴더 `disclosure-check-web`에 저장합니다.

## 8. 오류 확인

로그인 실패 시 계정 등록 여부와 비밀번호를 확인합니다. 처음 이용하면 회원가입이 필요합니다. 자료 조회가 실패하면 Backend 상태와 `/health/db`를 확인합니다. 공시 원문 제공 여부나 외부 API 제한에 따라 조회가 실패할 수 있으며 오류를 화면에 표시합니다.

분석이 대기 상태에 머물면 AI Worker와 RabbitMQ를 확인합니다. 분석 실패와 보고서 저장 실패는 별도로 표시합니다. 저장 재시도는 보존된 AI 상태 파일을 사용하는 Worker에서 수행합니다. 빌드 배포에는 `/api` reverse proxy와 SPA fallback이 필요합니다.

기업 목록의 업데이트 공시 배지는 DART 또는 SEC에서 조회한 최근 90일 전체 공시 건수입니다. 기업명 아래의 최근 업데이트 날짜는 조회한 최신 공시 날짜와 저장된 메모 및 보고서 날짜 중 가장 최근 값입니다. 메모와 AI 보고서는 해당 기업의 저장 건수를 표시합니다. 산업군은 네이버 금융의 종목별 업종 코드와 업종명 응답을 사용합니다. 기업별 정보는 최대 네 기업을 동시에 조회하며 5분간 재사용합니다. 실패를 0건이나 자료 없음으로 표시하지 않습니다.

기업 상세 메모 탭은 검색 옆의 메모 추가 버튼에서 모달을 엽니다. 모달의 파일 업로드와 작성 탭에서 해당 기업의 메모를 저장합니다. 저장 중에는 닫기를 막고 성공과 오류를 모달 안에 표시합니다.

공시 제목을 누르면 공식 원문을 새 탭으로 엽니다. 정정공시의 분석하기 버튼은 공시 분석 모달을 열며 해당 기업 메모와 버전을 선택할 수 있습니다. 모달의 분석 시작에서 공시를 등록하고 분석을 접수합니다. 모달을 여는 동작은 자료를 등록하지 않습니다.


선택 입력과 날짜 선택은 shadcn-vue의 Select, Calendar와 Popover를 사용합니다. 검토 보고서는 접기 버튼 없이 항상 펼쳐 표시하며, 출처와 원문 인용 목록만 기본으로 닫힌 토글에서 확인합니다. 추가 확인 사항 박스는 화면에 표시하지 않으며 서버 보고서 자료는 보존합니다.

작업 결과와 오류는 shadcn-vue Sonner 토스트로 화면 상단 중앙에 표시합니다. 메모 추가와 삭제, 관심종목 변경, 계정 변경과 다운로드에 알림을 연결했습니다. 분석 시작 및 진행 중 작업의 완료나 실패도 알립니다. 기존 완료 작업을 처음 조회할 때는 완료 알림을 반복하지 않습니다. 계정 모달을 포함한 기본 dialog 위에서도 같은 위치에 표시하며 비밀번호 변경 후 로그인 이동에도 성공 알림을 한 번 표시합니다.

기업 상세는 로고와 기업명을 왼쪽 위에 두고, 현재가와 등락률을 아래에 표시합니다. 그래프와 지표는 오른쪽에 배치하며 카드 테두리는 사용하지 않습니다. 그래프는 데스크톱 190px 및 64px, 작은 화면 130px 및 54px 크기를 유지합니다.

기업 상세에는 KRX 시세의 시가, 고가, 저가와 거래량을 표시합니다. 현재가 아래에는 당일 가격을, 오른쪽에는 거래량을 포함한 지표를 2열 3행으로 배치합니다. 상세와 스켈레톤의 상단 여백은 데스크톱 72px, 모바일 48px입니다.

상세 상단은 기업 정보와 현재가 행, 차트와 지표 행으로 구분합니다. 아래 행은 작은 그래프, 당일 가격 목록, 나머지 지표 순서입니다. 모바일에서는 나머지 지표를 다음 줄로 배치합니다.
