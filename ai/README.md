# 정정공시 메모 영향 분석

## 1. 실습 또는 과제 요구사항

`AI-Agent Capstone(+MCP).pdf`의 인쇄 페이지 69부터 73까지에서 Harness 구성과 평가표를 확인했습니다. 업무에 맞는 State와 Graph, 모델의 도구 선택과 근거 제시, 상태 저장과 재개, 진행 이벤트, MCP와 인증 및 오류 처리가 평가 대상입니다. 기본 배점은 100점이며 대기열은 가산점 10점입니다. 확인한 구간에는 제출 파일명과 압축 형식이 명시되지 않았습니다.

사용자가 처음 전달한 흐름도는 자료 조회와 기본 분석, 선택한 관점의 병렬 분석, 공유 조회와 결과 취합을 요구합니다. 보고서는 원래 메모를 보존하고 정정 내용과 수정 제안, 출처와 제한 사유를 포함해야 합니다. 전체 실행은 120초와 60,000토큰, 모델 최대 8턴으로 제한합니다. 보고서용 30초와 12,000토큰, 모델 1턴을 확보합니다. 관점별 모델 호출과 같은 도구의 호출은 재시도를 합쳐 각각 최대 3회입니다.

후속 사용자 지시에 따라 외부 금융 자료는 OpenDART, 학술검색은 Google Scholar로 범위를 좁혔습니다. **조회와 저장 함수 및 MCP 서버는 백엔드 담당 범위입니다. AI는 해당 도구의 호출과 응답 처리를 담당합니다.** AI 안에 추가했던 외부 API 직접 호출 코드와 MCP 서버를 제거했습니다. OpenDART와 SerpApi 키는 백엔드에서 설정해야 하며 AI의 설정 예시에는 포함하지 않았습니다.

원격 main의 `2825afc`를 충돌 없이 가져왔습니다. Business MCP의 업무 도구 7개, External MCP의 공시 조회, RAG MCP의 색인과 검색 도구에 AI 호출부를 맞췄습니다. 백엔드에는 로컬 코드 추가나 수정이 없습니다.

## 2. 요구사항 적용 위치

`disclosure_ai/graph.py`의 `AnalysisGraph.build`는 State와 S1, S2, S3의 연결을 정의합니다. `initial.py`는 S1의 입력 수집과 RAG 준비, 기본 분석을 실행합니다. `perspectives.py`는 S2에서 선택한 관점의 분기와 조회 반복을 처리합니다. `reporting.py`는 S3의 결과 취합과 보고서 생성 및 저장을 처리합니다. 단계 이름과 체크포인트의 상태 구조는 유지했습니다.

`harness.py`는 호출 전 예산을 예약하고 SQLite에 누적 사용량을 기록합니다. 기본 분석의 최대 출력은 사용자 요청에 따라 4,000토큰으로 늘렸습니다. 관점 분석은 1,500토큰, 보고서와 출력 검사는 2,000토큰을 유지합니다. 역할별 입력과 출력 한도, 재시도와 형식 복구가 같은 예산을 사용합니다. 출력 길이 제한으로 JSON이 끊기면 같은 한도에서 한 번 형식 복구를 요청합니다. 조회 캐시 키에는 작업과 접근 범위, 도구 이름과 인자가 들어갑니다. 진행 중인 같은 조회도 한 번만 실행하고 결과를 공유합니다.

`worker.py`는 백엔드 작업 ID로 내부 context를 조회하고 메모 버전과 공시 접수번호를 고정합니다. `tools.py`는 상태와 관점 결과를 Business MCP로 전달합니다. 단계 진행과 모델 및 조회 호출 전에 취소 상태를 확인합니다. `api.py`의 선택적 접수 경로는 사용자 JWT로 메모 접근 권한을 먼저 확인하고 내부 context와 대조합니다.

`documents.py`는 제공된 ZIP 원문을 파싱하는 AI 측 코드입니다. 외부 API를 호출하지 않습니다. ZIP 크기와 파일 수를 제한하고 정정표의 문서 ID와 행 위치를 보존합니다. 명확한 공백 차이만 있고 복잡한 표 구조가 없을 때 기본 분석 모델을 생략합니다. 금액, 날짜, 기업명과 계약 항목은 일반 분석으로 진행합니다.

## 3. 파일별 구현 내용

| 파일 | 담당 역할 |
| --- | --- |
| `graph.py` | 공유 상태, 단계 순서와 분기 연결 |
| `initial.py` | 공시와 메모 수집, RAG 준비, 기본 영향 분석 |
| `perspectives.py` | 선택한 관점 실행, 추가 조회와 결과 등록 |
| `reporting.py` | 결과 취합, 보고서 작성과 대체 보고서, 저장 |
| `harness.py` | 모델 및 도구 호출의 예산, 제한과 재시도 |
| `ledger.py` | SQLite 실행 기록, 보고서와 이벤트 보존 |
| `output.py` | 민감 정보 마스킹, 제한 문장과 모델 출력 검사 |
| `documents.py` | 공시 응답 변환, 제공된 ZIP 처리와 출처 대조 |
| `business.py`, `tools.py` | MCP 통신과 백엔드 도구의 인자 변환 |
| `worker.py`, `api.py`, `local.py` | 대기열과 선택적 API 및 로컬 실행 진입점 |


`schemas.py`는 고정 요청과 모델 출력 형식을 정의합니다. 관점은 백엔드와 같은 `INDUSTRY_CONTRACT`, `FINANCE`, `FX_HEDGE`를 사용합니다. 수정 제안의 영향 유형도 백엔드 Enum과 맞췄습니다. 모델이 선택할 조회는 `local_search`, `financial`, `academic`으로 제한했습니다.

`ledger.py`의 `Ledger`는 시작 시각, 예약 토큰, 모델 턴과 도구 횟수, 보고서와 이벤트를 보존합니다. `Harness.model`은 역할별 지시문과 OpenAI 구조화 응답을 사용합니다. `output.py`의 `mask`는 인증키 패턴과 이메일 및 휴대전화 패턴을 가립니다. `safe_text`는 투자 권유와 검사 권한을 주장하는 문장을 규칙으로 제외합니다. `review_output`은 문장별 의미 판별을 모델에 요청하고 허용된 서술만 남깁니다. 이 호출도 전체 8턴과 토큰 및 시간 예산에 포함합니다. 검사 실패나 예산 소진 시 자유 서술을 제외하고 대조된 원문 근거와 처리 상태를 보존합니다. 실제 모델 호출에서 사실 설명과 수정 제안 2개를 유지하고 투자 권유 및 검사 지시문 사례 4개를 제외했습니다. 이 6개 사례로 전체 판별 정확도를 보장할 수는 없습니다.

`tools.py`는 백엔드 MCP에 연결해 도구 목록을 확인하고 허용한 이름만 호출합니다. 현재 백엔드 MCP는 내부 네트워크에서 접근하도록 설계돼 있습니다. Business MCP가 내부 API 인증키를 관리하므로 AI는 이 키를 MCP 헤더로 전달하지 않습니다. 등록되지 않은 도구는 `TOOL_NOT_AVAILABLE`을 반환하며 직접 조회로 우회하지 않습니다. 모델에는 MCP 오류 원문을 전달하지 않습니다. `business.py`는 상태와 보고서 저장 요청을 실제 Business MCP 도구로 변환합니다.

`worker.py`는 기존 RabbitMQ 작업 메시지를 소비합니다. 브로커 스레드와 분석 실행을 분리해 모델 호출 중에도 heartbeat를 처리합니다. 재시도 발행 확인 후 원본을 ack하며 발행 실패 시 원본을 확인 처리하지 않습니다. 재시도 소진 시 기존 상태 API로 실패를 기록하고, 보존한 보고서가 있으면 재저장 가능한 상태를 유지합니다. 백엔드 자체가 응답하지 않으면 최종 상태 기록은 보장할 수 없으며 실패 큐와 로컬 상태를 확인해야 합니다.

`local.py`는 고정 메모 JSON과 제공된 공시 ZIP으로 같은 그래프를 실행하는 검증 경로입니다. 외부 조회를 수행하지 않으며 추가 조회 요청에는 `BACKEND_TOOL_REQUIRED`를 반환합니다. 로컬 보고서를 보존하고 업무 DB 저장 대기를 명시합니다. `api.py`는 선택적인 내부 접수, 결과 조회, 이벤트 스트림과 재저장을 제공합니다.

`pyproject.toml`은 백엔드와 분리된 Python 패키지이며 `uv.lock`으로 의존성 버전을 고정합니다. `tests/`의 도구 구현은 모의 서버 또는 테스트 대체 함수입니다. 배포용 조회 함수가 아닙니다. `live_smoke.py`는 명시적으로 실행할 때 실제 OpenAI 모델의 기본 분석과 보고서 응답 형식 및 출력 검사 6개 사례를 확인합니다. `tests/live_runtime.py`는 명시적으로 선택해 실제 RabbitMQ 수신부터 백엔드 MCP와 OpenDART, 모델, pgvector와 보고서 저장을 검사합니다. 일반 테스트에서는 유료 API 검사를 수집하지 않습니다.

## 4. 전체 실행 및 처리 흐름

기본 업무 경로는 백엔드가 발행한 `RUN_ANALYSIS` 메시지입니다. worker는 `task_id`로 고정 입력을 읽습니다. 완료되거나 취소된 작업은 재실행하지 않습니다. 동일한 상태 저장소는 worker 한 개가 사용합니다.

S1은 백엔드 MCP에 공시와 고정 메모를 요청합니다. 필수 자료가 부족하면 사유를 보존하고 보고서 생성으로 진행합니다. 자료가 있으면 정정표와 관련 문단 및 메모를 문맥으로 구성합니다. 기본 분석은 메모의 실제 문장과 출처를 대조하고 확인할 수 없는 제안을 `HOLD`로 보류합니다.

S2는 선택한 관점의 질문과 이유를 보존하고 해당 관점만 병렬 실행합니다. 추가 자료가 필요하면 확보한 문서를 검색하거나 백엔드의 재무 또는 학술 도구를 호출합니다. 외부 도구 인자는 공시 식별자와 공개 연구 주제로 제한합니다. 메모 원문을 학술 검색어로 전송하지 않습니다. 완료, 근거 부족, 한도 도달과 실패를 구분합니다. 도구 오류와 제한 사유는 보고서까지 보존합니다.

S3는 기본 분석과 관점 결과를 모읍니다. 보고서 모델이 실패하면 확보한 정정 내용과 메모 영향, 수정 제안, 관점 결과 및 실패 사유를 정상 보고서와 같은 여섯 항목으로 구성합니다. 본문 항목 제목은 한국어로 표시합니다. 보고서는 저장 요청 전에 로컬에 기록합니다. 저장 실패 시 보고서 내용을 유지하며 같은 작업 ID로 저장만 다시 요청합니다. 원래 메모를 수정하는 도구는 호출하지 않습니다.

## 5. 백엔드 도구와 호출 계약

현재 main의 실제 MCP 도구를 호출합니다. 모델 내부의 조회 이름은 `tools.py`에서 아래 도구로 변환합니다.

| 서버 | 도구 | 인자와 처리 |
| --- | --- | --- |
| Business MCP | `get_analysis_context`, `get_analysis_status` | `task_id`로 고정 메모와 상태를 확인합니다. |
| Business MCP | `report_analysis_event`, `update_analysis_state` | 단계와 진행 이벤트를 전달합니다. |
| Business MCP | `register_perspective`, `update_perspective` | 관점 선택과 결과를 전달합니다. |
| Business MCP | `save_analysis_report` | `task_id`, `content`, `report`, `has_warnings`, `no_additional_analysis_reason`을 전달합니다. |
| External MCP | `get_disclosure` | `receipt_no`로 원문과 표, 공식 메타데이터를 받습니다. |
| RAG MCP | `ensure_analysis_index` | `task_id`의 메모와 공시 색인을 준비합니다. |
| RAG MCP | `search_evidence` | `task_id`, `query`, `top_k`로 근거를 조회합니다. |

공시 응답은 원문 텍스트와 표, 파일 위치를 AI 분석 문맥으로 변환합니다. 공식 문서 ID가 없으면 접수번호와 내용 해시로 작업 내 식별자를 만듭니다. RAG 근거는 백엔드 문서 ID와 청크 번호를 사용하고 파일과 표 위치를 보존합니다. 출처 URL과 공개 시점은 조회 응답을 우선합니다. RAG 색인이나 검색이 실패하면 실패 사유와 확보한 원문을 보존합니다.

재무 조회는 백엔드가 OpenDART 재무정보를 조회하는 MCP 도구를 제공하고 AI가 그 결과를 분석하는 구조입니다. 조회 계약에는 기업코드와 사업연도, 보고서 종류, 연결 또는 별도 기준을 명확히 정해야 합니다. 반환값에는 계정명, 금액과 단위, 대상 기간 및 출처가 필요합니다. 현재 이 계약과 도구 구현은 미완료입니다.

`financial`, `academic`은 현재 백엔드에 구현되지 않아 `TOOL_NOT_AVAILABLE`을 반환합니다. 해당 조회의 미완료 사유는 보고서에 남습니다. 백엔드 도구가 구현되면 실제 이름과 인자에 맞춰 이 두 호출을 연결해야 합니다. AI는 업무 DB나 외부 자료 API를 직접 조회하지 않습니다.

토큰은 호출 전에 입력과 최대 출력을 보수적으로 예약합니다. 실제 사용 토큰은 별도 이벤트로 남기며 예약값을 청구 토큰으로 해석하지 않습니다. 비용의 금액 환산은 구현하지 않았습니다. 문서 색인과 벡터 검색은 RAG MCP가 담당합니다. 제공된 ZIP만 사용하는 로컬 경로와 RAG 장애 시 보조 검색에는 단어 일치 방식을 사용합니다.

## 6. 설정과 실행 방법

설정 예시는 [.env.example](.env.example)에 있습니다. 실제 키는 기록하지 않았습니다. AI에는 `OPENAI_API_KEY`를 전달합니다. 기본 모델은 `gpt-4.1-mini`입니다. `INTERNAL_API_KEY`는 Business MCP의 백엔드 설정입니다. OpenDART와 SerpApi 키는 조회를 담당할 백엔드에서 사용합니다.

Python 3.12 이상에서 이 패키지의 의존성을 설치합니다. `BUSINESS_API_BASE_URL` 기본값은 `http://127.0.0.1:8080`, `BUSINESS_MCP_URL` 기본값은 `http://127.0.0.1:8081/mcp`입니다. 백엔드 Compose 내부 네트워크에서는 각각 `http://business-api:8080`, `http://business-mcp:8081/mcp`를 사용합니다. `EXTERNAL_MCP_URL` 기본값은 `http://127.0.0.1:8083/mcp`, `RAG_MCP_URL` 기본값은 `http://127.0.0.1:8082/mcp`입니다. Compose 내부에서는 서비스 이름 `external-mcp`, `rag-mcp`를 사용합니다. 호스트에서 AI를 실행할 때는 해당 MCP 주소에 실제로 접근할 수 있어야 합니다.

기본 실행 명령은 `python -m disclosure_ai.worker --state <AI 상태 파일의 절대 경로>`입니다. 기존 백엔드와 같은 `RABBITMQ_URL`, `RABBITMQ_EXCHANGE`, `RABBITMQ_ANALYSIS_QUEUE`를 설정합니다. 큐 없이 작업 한 건을 확인할 때는 `--task-id <실제 작업 UUID>`를 추가합니다. 상태 파일은 재저장과 재개에 필요하므로 보존합니다.

백엔드 없이 검증할 때는 `python -m disclosure_ai.local --input <입력 JSON 경로> --filing <공시 ZIP 경로> --state <상태 파일 경로>`를 사용합니다. 입력은 아래 형식입니다. 이 경로의 메모는 사용자가 준비한 고정 입력이며 업무 권한 검증을 대신하지 않습니다.

```json
{
  "request": {
    "analysis_task_id": "00000000-0000-0000-0000-000000000001",
    "memo_id": "00000000-0000-0000-0000-000000000002",
    "base_memo_version": 1,
    "disclosure_receipt_no": "20261020000245",
    "company_name_snapshot": "분석 대상 기업명",
    "corp_code": null,
    "thread_id": "고정된 작업 식별자"
  },
  "memo_text": "검증용 고정 메모 원문입니다."
}
```

로컬 결과의 `LOCAL_SAVED`와 `PENDING_BACKEND`는 로컬 보존과 업무 DB 저장 대기를 나타냅니다. 추가 외부 조회의 미실행 사유도 남습니다.

선택적인 AI API는 `uvicorn disclosure_ai.api:app --host 127.0.0.1 --port 8000 --workers 1`로 실행합니다. `AI_INTERNAL_TOKEN`과 `AI_STATE_PATH`가 필요합니다. `POST /internal/analyses`에는 위 `request` 객체와 `Authorization: Bearer <로그인 토큰>`, `X-AI-Token: <내부 토큰>`을 전달합니다. 같은 요청과 헤더로 `/internal/analyses/{task_id}/result`, `/events`, `/retry-save`를 POST 호출합니다.

실행과 검증 환경은 저장소 밖에 구성했습니다. 사용자 요청으로 삭제한 `작업`, `제출`, `산출물` 폴더를 저장소에 다시 만들지 않았습니다. `ai/build`의 과거 MCP 서버 복사본도 도구 제거 지시에 따라 삭제했습니다. 나머지 `ai/build`와 `ai/disclosure_ai.egg-info`는 예전 생성물이며 현재 소스와 다를 수 있습니다. 현재 실행 기준은 `disclosure_ai/`입니다.

## 7. 검증 결과와 미완료 범위

코드 분리와 기본 분석 출력 한도 확장 후 테스트 28개가 9.32초에 통과했습니다. Ruff 검사와 형식 검사도 통과했습니다. 별도 PostgreSQL에서 실제 Business API와 MCP를 사용해 저장 실패 후 재저장, 취소와 메모 버전 보존을 확인합니다. 이 기본 검사의 외부 응답과 임베딩은 테스트 입력으로 대체합니다.

별도 명시 실행인 `tests/live_runtime.py`도 34.86초에 통과했습니다. 원본 백엔드와 실제 RabbitMQ, OpenDART, OpenAI 모델 및 임베딩, pgvector를 사용했습니다. 인증된 테스트 사용자의 분석 접수부터 큐 수신과 기본 분석, 보고서 저장까지 실행했습니다. 메모와 공시의 1,536차원 벡터 저장, 근거 검색, 보고서 한 건 저장과 메모 원문 보존을 확인했습니다. 검증용 사용자와 DB를 사용했으며 실제 사용자 화면은 확인하지 않았습니다. 가져온 백엔드 테스트의 postgres 마커 등록 경고 25개가 표시됐습니다.
출력 검사 테스트는 모의 모델로 위험 문장 제외와 예산 소진 시 서술 제거를 확인합니다. 별도 실제 호출에서는 기본 분석과 보고서 생성, 출력 검사까지 모델 3회를 사용해 6개 사례를 통과했습니다. 최초 검증에서는 검사 권한 주장 문장이 남았고 지시문 보완만으로 해결되지 않아 규칙 검사에도 해당 유형을 추가했습니다. MCP 클라이언트는 실제 HTTP 통신으로 도구명과 오류 코드 처리 및 오류 원문 비공개를 검사합니다. 그래프 분기와 예산, 중복 조회, 체크포인트 재개, worker 재발행 확인과 로컬 보고서 보존도 검사합니다.

최신 External MCP를 원본 그대로 실행하고 AI 클라이언트로 실제 OpenDART 접수번호 `20261020000245`를 조회했습니다. 미로바펀즈의 공시 원문 1개, 정정 항목 7개, 표 10개를 받았고 공식 메타데이터에서 기업코드와 공시일을 확인했습니다. 정정표 전체 추출 여부는 false로 유지됐습니다. 이 검증은 External MCP의 실제 조회와 AI 응답 변환을 확인한 범위입니다. 이후 명시 실행 검사에서 실제 RAG 저장소와 보고서 저장까지 확인했습니다.

실행되지 않던 Colima를 시작하고 검증 전용 PostgreSQL과 RabbitMQ 컨테이너를 사용했습니다. 백엔드 Compose의 postgres 키가 중복돼 해당 파일을 수정하지 않고 의존 서비스를 별도로 실행했습니다.

앞선 단계에서 실제 OpenAI 기본 분석과 보고서 생성 응답을 확인했습니다. 이후 직접 조회 구현을 작성하면서 OpenDART 문서 1개와 정정 행 7개, 삼성전자 재무 229개 항목, Google Scholar 검색 결과 5건을 확인했습니다. 해당 직접 조회 구현은 사용자 지시에 따라 제거했으며 이 결과를 현재 AI의 직접 조회 기능으로 보고하지 않습니다.

현재 미완료 범위는 백엔드의 재무 및 학술 조회 도구 연결, 사용자 화면 연동, 다양한 실제 보고서에 대한 의미 판별 정확도 평가입니다. 정상 상태와 장애 상황 모두에서 오류가 없다고 보장하지 않습니다. 백엔드 파일의 로컬 변경은 없습니다.

## 8. 트러블 슈팅

실제 기본 분석 응답이 2,000토큰에서 잘려 LengthFinishReasonError가 발생했습니다. 사용자 요청에 따라 기본 분석 최대 출력을 4,000토큰으로 늘렸고 길이 초과를 기존 1회 형식 복구 경로에 포함했습니다. 전체 120초와 60,000토큰 및 모델 8턴 제한은 유지합니다. 재검증에서 기본 분석과 보고서 저장을 확인했습니다. 최초 실제 서비스 검사에는 검색 서버 이름의 대소문자 오류가 있어 검증 코드를 수정한 뒤 다시 통과했습니다.

MCP SDK의 이전 함수에서 사용 중단 경고가 발생해 `streamable_http_client`와 전용 HTTP 클라이언트로 바꿨습니다. 모의 MCP 서버와 실제 HTTP 통신으로 호출과 오류 본문 비공개 처리를 확인합니다.

SQLite 연결을 만든 이벤트 루프와 다른 테스트 스레드에서 접근해 오류가 발생했습니다. 테스트 초기화를 TestClient의 같은 이벤트 루프에서 수행하도록 수정했습니다. 연결의 스레드 제한은 유지했습니다.

과거 OpenDART 재실행 실패는 원문이 제공되지 않는 공시의 `014` 응답이 원인이었습니다. 이 진단은 조회 구현 제거 전의 결과입니다. 현재 AI는 백엔드 도구가 반환한 오류 코드와 미수행 사유를 보고서에 보존합니다.

백엔드의 도구 구현 범위를 확인하기 전에 AI에 조회 함수를 추가했습니다. 사용자 지시를 받아 직접 조회 모듈과 MCP 서버 및 전용 테스트를 제거했습니다. 이번 main 갱신에서 구현된 도구의 실제 규격에 맞춰 AI 호출 부분을 조정했습니다.

## 9. 첨부 흐름도와 현재 검증 범위

첨부 원본의 REQUEST, S1부터 S3, 하네스 설명을 다시 대조했습니다. ECOS, KRX와 Tavily는 이후 사용자의 OpenDART 및 학술 검색 지시로 범위에서 제외했습니다. 조회 함수와 MCP 서버 구현도 후속 지시에 따라 백엔드 담당으로 유지합니다.

고정 입력과 중복 방지, 관점 선택 및 병렬 실행, 조회 공유, 누적 예산과 체크포인트, 출력 검사 및 대체 보고서 보존은 AI 테스트로 확인했습니다. 실제 모델의 기본 분석과 보고서 형식 및 출력 검사 사례, 실제 OpenDART 공시 응답도 별도로 확인했습니다. 업무 DB 저장 실패 후 동일 작업 재저장과 메모 버전 보존은 실제 Business API 및 MCP와 별도 PostgreSQL로 검증했습니다.

전체 요구사항의 완료는 아직 확인되지 않았습니다. `financial`, `academic`에 연결할 백엔드 도구가 없으며 이번 작업의 백엔드 기준은 `2825afc`입니다. 실제 pgvector와 RabbitMQ 및 외부 API 연결 검사는 통과했지만 사용자 버튼부터 화면 표시까지는 미검증입니다. 백엔드 파일을 수정하지 말라는 사용자 지시에 따라 미구현 조회 도구를 AI에 추가하지 않았습니다.
