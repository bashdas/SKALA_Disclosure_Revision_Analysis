# 정정공시 메모 영향 분석

에이전트의 핵심 목적은 기존 메모의 관점과 가정 중 이번 공시로 새롭게 고찰해야 할 관점을 근거와 함께 제시하는 것입니다. 기본 분석은 `review_points`에 기존 메모의 관점, 공시에서 확인한 사실, 다시 고찰할 이유, 검토 질문과 확인할 자료를 작성합니다. 각 항목은 기준 메모와 이번 공시 양쪽의 검증된 원문을 연결해야 합니다. 직접 고칠 문장이 없어도 관점을 제시할 수 있으며, 연결 근거가 없는 일반론은 제외합니다.

문장 수정 제안(`proposals`)은 보조 결과입니다. 심화 분석 분야의 선택 여부나 완료 여부와 별개로 근거 있는 기본 재검토 관점은 보고서와 화면에 보존합니다. 기존 보고서는 그대로 유지되며 새 분석부터 이 구조를 사용합니다.

## 과거 공시 조회

국내 정정공시는 기본 분석 전에 DART 연결 목록에서 최초 공시와 직전 공시를 확보합니다. 두 대상이 같으면 한 번만 조회합니다. 신규공시도 기존 계약 변경·해지나 원공시 참조가 있으면 기본 분석의 `history_assessment`로 필요성을 명시하고(`REQUIRED/NOT_REQUIRED/ALREADY_AVAILABLE/UNAVAILABLE`), `REQUIRED`이면 `history_request`를 통해 실제 조회를 요청하고, 원문이 추가되면 기본 분석을 한 번 재수행합니다. 공식 `NEW/CORRECTION/UNKNOWN` 분류는 과거 조회 여부와 별개로 유지합니다.

심화 분석의 `Lookup.tool`에는 `disclosure_history`를 사용할 수 있습니다. `query`는 조회 목적, `evidence`는 이번 공시의 근거, `receipt_no`는 확인한 대상 접수번호 또는 null입니다. `services/history.py`가 `history_family`, `history_search`, `history_document`를 통해 기존 External MCP의 연결 목록, 공시 목록, 원문 도구를 호출합니다. MCP 전체 도구를 모델에 무제한으로 노출하지 않습니다.

공식 연결 목록을 우선 사용하고, 목록 밖에서는 현재 본문이 명시한 접수번호·DART 링크·공시일만 추적합니다. 날짜 검색은 같은 회사의 해당 날짜로 제한합니다. 명시된 문서명으로 후보를 줄여도 본문의 계약 상대방·제품·대상을 별도로 대조하며, 후보가 중복되거나 일부 원문을 못 받으면 임의로 연결하지 않습니다. 원공시를 찾은 뒤에는 그 원공시의 연결 이력도 확인합니다. 현재 이후의 공시는 사용하지 않습니다.

과거 원문 조회는 분석당 서로 다른 접수번호 최대 3건(실패·후보 대조 포함), 동시 조회 2건, 누적 30초로 제한합니다. 로컬 실행 원장의 `history_budget`에 시간·접수번호를 보존하므로 재시작으로 예산이 초기화되지 않습니다. 기존 전체 120초, 모델 사용량, 저장용 시간 예산도 유지합니다. 백엔드 업무 DB 마이그레이션은 필요하지 않습니다.

과거 원문은 작업의 `documents/context`에 포함하되 모델에는 별도 `history_context`로 전달합니다. 현재 공시의 정정표와 합치지 않습니다. `local_search` 및 RAG 추가 조회에서도 확보한 과거 문서를 함께 검색합니다. 보고서 JSON의 `disclosure_history`와 Markdown의 '조회한 과거 공시와 비교 범위'에 확보한 문서, 역할, 연결 근거와 미확인 범위를 저장합니다. `history_comparisons`에는 과거·현재 사실과 해석을 양쪽 원문 인용으로 검증한 비교 항목을 작성합니다. 새 비교 항목의 과거·현재 사실과 해석은 출력 검사에서 허용된 문장만 보존합니다. 조건 미기재를 조건 불변으로 단정하지 않습니다. 원문 확보와 비교 완료를 구분하며, 체크포인트 기록 직전 중단된 원문도 로컬 스냅샷과 조회 캐시에서 복구합니다. 조회 실패 시 부분 분석을 계속하며 기존 사용자 보고서는 덮어쓰지 않습니다.

## LangSmith 추적

`ai/.env`에 `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY`,
`LANGSMITH_PROJECT=disclosure-ai-dev`를 설정합니다. 키는 커밋하지 않습니다.
워크스페이스나 리전에 따라 `LANGSMITH_WORKSPACE_ID`, `LANGSMITH_ENDPOINT`도 설정합니다.
프로젝트 루트에서 다음 명령으로 환경변수를 전달해 worker를 실행합니다.

```bash
cd ai
uv run --env-file .env python -m disclosure_ai.entrypoints.worker --state outputs/ai-state.sqlite
```

`.env`는 Python 진입점에서 자동으로 읽지 않습니다. 기존 worker는 환경변수를 적용해
다시 실행해야 합니다. Docker Compose를 사용하면 `backend/.env`에도 LangSmith 설정을
추가하고 `backend`에서 `docker compose up -d --build ai-worker`를 실행합니다.

분석은 `disclosure-analysis` trace로 기록되고, 그래프 노드와 OpenAI 및 MCP 호출은
하위 run으로 기록됩니다. `task_id` 메타데이터로 검색하고 같은 작업의 실행은
`thread_id=task_id`로 묶습니다. 체크포인트 복구용 ID는 기존 값을 유지합니다.
최상위 trace 출력에는 업무 상태와 경고를 기록합니다. 복구된 실패는 예외 대신
`SAVE_FAILED` 같은 결과로 반환될 수 있으므로 trace 성공 여부와 업무 상태를 함께 확인합니다.
MCP 서버 내부 처리와 분석을 생략한 별도 보고서 재저장 경로는 이 분석 trace 범위 밖입니다.

그래프 상태, 모델 프롬프트와 도구 결과에는 메모와 공시 원문이 포함될 수 있습니다.
본문을 전송하지 않으려면 `LANGSMITH_HIDE_INPUTS=true`, `LANGSMITH_HIDE_OUTPUTS=true`를
설정합니다. 로컬 SQLite ledger와 체크포인트는 복구용으로 계속 사용합니다.

## 1. 실습 또는 과제 요구사항

강의 자료 `AI-Agent Capstone(+MCP).pdf`의 69쪽부터 73쪽까지와 첨부 흐름도를 기준으로 구현했습니다. 고정된 메모와 정정공시를 분석하고, 필요한 관점만 병렬로 실행한 뒤 근거를 포함한 보고서를 자동 저장합니다. 원래 메모는 수정하지 않습니다.

외부 자료는 사용자가 지정한 OpenDART와 Google Scholar로 제한했습니다. 외부 API 조회 함수와 키, 업무 DB 및 RAG 저장소는 백엔드가 담당합니다. AI는 백엔드 MCP 호출과 분석 흐름을 담당합니다. 내부 리포트 참조는 RAG MCP의 작업별 기업 검색으로 처리합니다. 로컬 JSON과 임베딩 검색은 테스트에서만 사용합니다. External MCP의 공시 원문, 재무제표와 학술 검색 도구에 연결합니다.

전체 분석은 120초, 입력과 출력 합계 예약 80,000토큰, 모델 12턴으로 제한합니다. 일반 분석은 64,000토큰과 10턴까지 사용하며, 보고서 요약과 출력 검사를 위해 30초와 16,000토큰 및 2턴을 남깁니다. 사용자 요청에 따라 기본 분석의 최대 출력은 4,000토큰입니다. 관점 분석은 입력 6,000토큰과 출력 1,500토큰, 기본 분석과 보고서는 입력 10,000토큰, 보고서 출력은 2,000토큰입니다.

## 2. 요구사항 적용 위치

`workflow/graph.py`는 REQUEST, S1, S2, S3, REPORT_AGENT, SAVE를 연결합니다. S1은 자료 취합과 검색 준비 및 기본 분석입니다. S2는 선택된 관점의 모델 호출 한 번을 병렬로 실행합니다. S3는 STATUS, KEY, SHARED, RESULT, JOIN 노드로 조회 요청을 처리하고, 자료를 받은 관점이 있으면 S2로 돌아갑니다. 종료된 관점은 재호출하지 않습니다.

`harness/runtime.py`는 병렬 모델 호출 전에 예산을 예약하고 관점별 최대 3턴을 강제합니다. 모델 요청은 최대 20초이며 남은 시간보다 길게 실행하지 않습니다. 일시 오류는 추가 2회, 구조화 응답의 형식 복구는 1회까지 허용하고 재시도도 예산에 포함합니다.

`harness/lookup.py`는 자료 조회와 최초 보고서 저장을 호출당 최대 10초, 같은 도구 전체 최대 3회로 제한합니다. 동일한 요청의 결과와 진행 중 호출을 공유하고, 조회 대기 한도에 도달한 관점은 종료합니다. `workflow/execution.py`는 시간 초과와 예상하지 못한 실행 오류에서도 보고서를 로컬에 보존합니다.

## 3. 파일별 구현 내용

```text
ai/
├── disclosure_ai/
│   ├── entrypoints/
│   │   ├── worker.py        RabbitMQ 소비와 작업 실행
│   │   ├── api.py           선택적 내부 HTTP 접수와 결과 조회
│   │   └── local.py         제공된 메모와 ZIP의 로컬 실행
│   ├── workflow/
│   │   ├── graph.py         State와 서브그래프 연결
│   │   ├── initial.py       S1 자료 취합과 기본 분석
│   │   ├── perspectives.py  S2 관점 선택과 분석 응답
│   │   ├── shared.py        S3 공유 조회와 관점 재개
│   │   ├── reporting.py     보고서 생성과 저장, 비상 보고서
│   │   └── execution.py     공통 실행, 복구와 재저장
│   ├── services/
│   │   ├── business.py      MCP 전송과 업무 도구 매핑
│   │   ├── tools.py         허용 도구 호출과 응답 변환
│   │   ├── documents.py     공시 처리와 근거 대조
│   │   └── research.py      내부 리포트 검색 연동과 제안 검증
│   ├── harness/
│   │   ├── runtime.py       모델 예산과 실행 한도
│   │   ├── lookup.py        조회 정규화와 동시 호출 공유
│   │   ├── ledger.py        실행 상태와 원문 및 보고서 보존
│   │   ├── transport.py     상태 동기화와 재저장 전송 제한
│   │   └── output.py        민감 정보와 투자 권유 출력 검사
│   ├── data/research_reports.json  기존 검증 리포트 전사 본문과 기업 정보
│   ├── prompts/            역할별 지시문
│   ├── schemas.py          고정 입력과 모델 응답 형식
│   └── errors.py           실행 한도 오류
├── tests/                  단위 검사, 백엔드 연결과 명시적 실제 실행 검사
├── .env.example
├── pyproject.toml
└── uv.lock
```

`services/business.py`는 Business MCP의 작업 context, 상태, 이벤트, 관점과 보고서 도구를 호출합니다. `services/tools.py`는 External MCP의 get_disclosure, get_financial_statements, search_academic_papers와 RAG MCP의 ensure_analysis_index, search_evidence를 AI 문맥으로 변환합니다. 자료 ID와 원문 위치 및 공개 시점을 보존하고, 응답에 포함된 내부 오류 원문은 모델에 전달하지 않습니다.

`services/research.py`의 ResearchIndex는 분석 대상 기업코드와 공시 기준일로 리포트를 선택합니다. 기본 목록은 iM증권의 2026년 2월 2일 삼성중공업 리포트 전사 본문이며 그래프의 선형 정보는 포함되지 않았습니다. 기업코드가 일치하고 발행일이 공시 기준일 이전 또는 같은 자료만 검색합니다. 메모 ID나 버전 연결은 필요하지 않습니다. SEC 공시는 공식 filed_at이 있어야 검색합니다. 현재 로컬 목록은 조직별 접근 제어를 구현하지 않은 검증용이며, 내부 리포트 운영 시 조직별 저장·검색 제한은 백엔드 RAG 연동에서 적용해야 합니다.

리포트는 쪽 경계와 원문 줄 범위를 보존한 약 1,200자 조각으로 나눴습니다. OpenAI text-embedding-3-small의 1,536차원 벡터로 변환하고 같은 AI 상태 SQLite의 research_embeddings에 보존합니다. 접근 범위, 모델 설정과 조각 본문 해시가 같은 경우 문서 임베딩을 재사용합니다. 검색어도 같은 모델로 변환한 뒤 코사인 유사도가 높은 세 조각을 선택합니다. 별도 검색 서버와 백엔드 RAG의 데이터베이스는 사용하지 않습니다. 임베딩 조회는 기존 도구 호출의 시간과 횟수 제한 안에서 실행합니다.

`services/documents.py`는 공시 표와 본문을 대조하고 원문 인용을 검증합니다. rowspan과 colspan으로 병합된 표의 열 위치를 복원해 후속 행의 변경도 추출합니다. 모델은 제공된 문서와 위치를 선택하고 코드는 유일하게 연결된 원문을 복원합니다. 직접 반환한 인용의 줄바꿈 차이도 확인된 원문 조각으로 복원하며 수치나 단어가 다른 인용은 받아들이지 않습니다. 로컬 ZIP은 메모리에서 크기와 파일 수를 제한해 처리합니다. 복잡한 표가 없고 모든 정정이 허용된 공백 차이일 때만 기본 분석을 생략합니다. 금액, 날짜, 기업명과 계약 조건 및 부정 표현 변경은 일반 분석으로 진행합니다.

`harness/output.py`는 규칙 검사 후 모델에 문장별 의미 검사를 요청합니다. 문장마다 연결된 근거가 실제 주장을 뒷받침하는지도 검사합니다. 이 검사도 전체 모델 예산을 사용합니다. 검사 실패나 예산 소진 시 자유 서술을 제외하고 검증된 원문과 처리 상태를 남깁니다. 원문에 들어 있는 명령은 지시로 실행하지 않습니다.

## 4. 전체 실행 및 처리 흐름

백엔드는 분석 요청의 권한과 고정 입력을 확인하고 RUN_ANALYSIS 메시지를 발행합니다. worker는 task_id로 작업을 조회한 뒤 조직과 메모 버전 및 공시 접수번호를 고정합니다. 완료되거나 취소된 작업은 재실행하지 않습니다.

S1은 공시와 메모를 병렬로 조회하고 정정표와 관련 문단을 모읍니다. AI 로컬 리포트 검색으로 찾은 조각도 기본 분석에 전달합니다. 선택된 관점의 local_search가 백엔드 RAG로 전달될 때도 해당 기업 리포트를 함께 검색합니다. 리포트 검색 실패는 경고로 남기고 기존 공시와 메모 분석을 이어갑니다. RAG 색인이나 검색의 실패 사유는 보존하며 확보된 자료로 분석을 이어갑니다. 해당 기업 리포트가 있으면 research 모델이 메모 발췌문과 공시 및 리포트 조각을 대조해 보완 항목과 재검토 위치를 별도로 작성합니다. 이 호출도 기존 전체 시간과 모델 호출 및 토큰 예산을 사용합니다. 실패한 경우에는 사유를 남기고 기본 메모 분석 결과를 보존합니다. 기본 분석의 수정 제안은 메모의 실제 문장과 원문 근거를 확인하고, 근거가 없거나 기존 메모 문장이 비어 있으면 HOLD로 보류하며 수정문과 근거 없는 설명을 비웁니다.

S2는 관점별 응답에서 완료, 근거 부족, 추가 조회 필요를 구분합니다. 추가 조회는 S3가 처리합니다. 같은 조건의 조회는 한 번만 실행하고 결과를 요청한 관점에 반환합니다. 학술 검색어는 고정된 공개 연구 주제로 제한해 사내 메모 문장을 외부 검색으로 보내지 않습니다. 모든 선택 관점이 종료되면 보고서를 작성합니다.

보고서는 확인된 정정 전후 표와 출처 번호를 표시합니다. 추가 관점의 선택 이유와 처리 상태는 짧은 표로 보여줍니다. 확인된 정정 내용, 메모 연결과 근거가 확인된 제안, 완료된 관점 결과를 요약 모델에 전달합니다. 같은 근거는 한 번만 보내고 출처 ID로 연결합니다. 요약은 최대 세 문장이며 각 문장은 출처에 연결됩니다. 향후 영향은 최대 세 항목으로 작성하고 성립 조건과 예상 결과를 구분합니다. 변경 사실에서 도출할 수 있는 실적, 계약 이행, 운영과 공시 해석의 가능성을 설명하며 투자 판단과 매매 및 자산 배분 제안은 제외합니다. 조건부 미래 영향도 연결된 근거와 인과관계를 출력 검사에서 확인합니다. 근거 부족 관점과 보류 제안은 분석 본문에서 제외하고 미작성 상태를 표시합니다. 내용이 없는 항목은 본문에서 생략하며 JSON의 sections 키는 비어 있는 구역도 유지합니다. 모델 생성 실패 시에도 출력 검사를 통과한 항목과 확인된 원문만 표시합니다. 저장 요청 전에 로컬에 보존하고 같은 task_id로 업무 DB에 저장합니다. 저장 실패 시 본문을 유지하며 재저장은 모델을 다시 호출하지 않습니다.

문맥 처리 실패는 단계와 사유를 남기고 보고서 경로로 이동합니다. 전체 실행 시간이 끝났거나 그래프 실행이 중단되면 마지막 체크포인트의 원문 근거와 처리 상태로 비상 보고서를 보존합니다. 남은 시간이 없으면 네트워크 저장을 추가로 실행하지 않고 SAVE_FAILED와 TIME_LIMIT을 반환합니다. 이후 재저장 경로로 복구할 수 있습니다.

재무 조회는 기업코드, 사업연도, 보고서 코드와 연결 또는 별도 구분을 받습니다. 관점이 지정하지 않으면 분석 기준일의 전년도 사업보고서와 연결재무제표(CFS)를 사용합니다. 연결 자료가 없다고 별도 자료로 자동 대체하지 않습니다. 금액 문자열과 원래 계정 정보를 보존하고 실제 공시일이 없거나 기준일 이후인 자료는 제외합니다. 기준일 당시의 수정 이력을 복원하는 기능은 없으므로 나중에 정정된 자료만 반환되면 분석 근거로 사용할 수 없습니다.

학술 검색은 SerpApi를 통해 Google Scholar 검색 요약을 받습니다. 메모 문장은 검색어로 전송하지 않습니다. 정확한 발행일을 확인할 수 없어 검색 연도의 상한을 기준일의 전년도로 제한하고 일반 연구 배경으로만 사용합니다. 논문 전문이나 특정 기업의 실적을 확인한 것으로 해석하지 않습니다.

## 5. 핵심 코드의 의도와 작동 원리

공유 조회 키에는 작업 ID, 접근 범위, 도구 이름과 정규화된 인자가 포함됩니다. 검색어의 유니코드와 공백, 기준일 표기를 정리합니다. 의미가 비슷한 서로 다른 검색어까지 같은 요청으로 합치지 않습니다. 캐시를 반환하기 전에도 취소와 접근 상태를 확인합니다.

SQLite의 lookup_jobs에는 조회 시작 전에 RUNNING과 시도 횟수를 저장합니다. 완료 후 결과와 종료 상태를 보존합니다. 재시작 시 중단된 조회를 식별하고 기존 누적 횟수와 시간 안에서 다시 실행합니다. 조회는 읽기 작업이고 보고서 저장은 task_id 기준의 백엔드 중복 방지 계약을 사용합니다. URL 또는 문서 ID와 내용 및 접근 범위가 같은 원문은 source_bodies에 한 번 보관하고 캐시에서는 참조로 재사용합니다. 같은 URL이라도 내용이 바뀌면 별도 원문으로 보존합니다.

상태 조회와 단계 및 이벤트 전달은 새로운 자료를 얻는 조회와 구분됩니다. transport.py가 남은 실행 시간, 전송당 10초와 최대 3회 시도, 추적 기록을 적용합니다. 진행 상태는 최신 값이 필요해 조회 캐시를 사용하지 않습니다. 사용자 재저장은 별도 10초 작업으로 최대 3회 시도하며 같은 보고서와 작업 ID를 유지합니다. 전체 분석의 모델 예산을 초기화하지 않습니다.

실행과 조회 기록은 task_id로 연결됩니다. 토큰은 호출 전 입력과 최대 출력을 예약하고 실제 사용량은 별도 이벤트에 남깁니다. 예약값은 청구 토큰과 다릅니다. 하나의 상태 파일에는 worker 한 개를 사용합니다. 여러 호스트에서 동시에 처리하려면 공유 실행 임대와 공용 저장소가 필요합니다.

## 6. 입력, 출력과 확인 방법

Python 3.12 이상과 pyproject.toml의 의존성을 사용합니다. 기본 분석 모델은 gpt-5.4-mini이며 OPENAI_MODEL로 변경할 수 있습니다. 기존 환경에 설정된 OPENAI_MODEL 값이 기본값보다 우선합니다. 이전 기본 모델의 실제 검사에서 근거 혼동과 유효한 조건부 영향 누락이 반복돼 기본값을 변경했습니다. 설정 이름은 .env.example에 있습니다. AI에는 OPENAI_API_KEY와 각 MCP 주소, RabbitMQ 주소를 전달합니다. OpenDART와 SerpApi 키는 백엔드 설정입니다. 실제 키는 소스에 기록하지 않습니다.

```bash
python -m disclosure_ai.entrypoints.worker --state /absolute/path/ai-state.sqlite
python -m disclosure_ai.entrypoints.worker --state /absolute/path/ai-state.sqlite --task-id <작업 UUID>
python -m disclosure_ai.entrypoints.local --input <입력 JSON> --filing <공시 ZIP> --state /absolute/path/local.sqlite
uvicorn disclosure_ai.entrypoints.api:app --host 127.0.0.1 --port 8000 --workers 1
```

패키지 설치 후 disclosure-ai-worker와 disclosure-ai-local 명령도 같은 진입점을 사용합니다. 기본 주소는 Business API 8080, Business MCP 8081, External MCP 8083, RAG MCP 8082입니다. 각 MCP는 /mcp 경로로 연결합니다. worker는 백엔드와 같은 RABBITMQ_URL, RABBITMQ_EXCHANGE, RABBITMQ_ANALYSIS_QUEUE를 사용합니다.

AI_RESEARCH_REPORTS_PATH를 생략하면 패키지의 data/research_reports.json을 사용합니다. 이 설정에 다른 JSON의 절대경로를 전달하면 리포트 목록을 교체할 수 있습니다. 각 리포트는 report_id, title, company_name, corp_code, published_at, url, source_file, text를 받습니다. 메모 연결 정보는 받지 않습니다. url은 원문 주소를 확인하지 못했으면 null로 둡니다. 목록 파일은 최대 5 MiB이며 report_id는 목록 안에서 고유해야 합니다. 원문에서 전사한 본문과 쪽 표기를 보존해야 합니다. 신규 의존성과 PDF 자동 추출은 추가하지 않았습니다.

결과 JSON의 research_reports에는 검색에 사용된 기업코드와 리포트 정보가 담깁니다. memo_supplements에는 메모에 추가할 내용과 이유 및 연결할 report_document_id와 report_location이, report_revisions에는 리포트 document_id, 원문의 페이지 및 줄 위치, 기존 문장과 수정안 및 이유가 담깁니다. 두 제안은 현재 공시와 리포트 근거가 함께 확인돼야 남습니다. 수정 위치가 검색한 원문 조각에 없으면 제외합니다. 기존 문장은 선택한 위치의 원문을 코드에서 복원해 보존합니다. 확정할 수 없는 수정은 after_text를 null로 두고 추가 확인 항목을 설명합니다. 기존 저장 요청의 report_json과 suggestions 본문에 결과를 포함했으며 저장 요청 필드와 일곱 sections 키는 유지했습니다. 메모와 리포트 원문은 자동 변경하지 않습니다.

로컬 JSON은 request 객체와 memo_text 문자열을 받습니다. request에는 analysis_task_id, memo_id, base_memo_version, disclosure_receipt_no, company_name_snapshot, corp_code와 thread_id를 포함합니다. 로컬 결과의 LOCAL_SAVED와 PENDING_BACKEND는 업무 DB 저장을 수행하지 않았음을 나타냅니다.

선택적인 AI API는 AI_INTERNAL_TOKEN과 AI_STATE_PATH를 사용합니다. POST /internal/analyses에는 고정 request 필드와 사용자 Authorization 헤더, X-AI-Token 헤더를 받습니다. /internal/analyses/{task_id}/result, /events, /retry-save도 같은 입력과 인증으로 POST 호출합니다.

기본 검사는 pytest tests로 실행합니다. 백엔드 연결 검사는 전용 TEST_DATABASE_URL과 backend/business-api, backend/shared, backend/business-api/tests를 포함한 PYTHONPATH가 필요합니다. tests/live_runtime.py는 명시적으로 지정하고 AI_LIVE_RUNTIME=1, 전용 DB와 RabbitMQ, OpenAI 및 백엔드 OpenDART 설정을 제공할 때만 실제 외부 서비스를 호출합니다. RAG와 업무 DB의 원본 마이그레이션이 필요합니다.

## 7. 실제 실행 및 검증 결과

리포트 참조 기능 검사 11개가 통과했습니다. 현재 모델 호출 한도 12턴과 토큰 한도 80,000에 맞춘 전체 AI 검사에서 90개가 통과했고 백엔드 연결 조건이 필요한 검사 2개는 생략됐습니다. 일반 분석의 10턴과 64,000토큰 한도, 보고서와 출력 검사의 예약 예산 및 재시작 후 누적 사용량 보존을 확인했습니다. 실제 OpenAI 임베딩으로 리포트 조각 18개를 저장했고, 기존 삼성중공업 검증 공시와 리포트로 실행한 분석에서 메모 보완 1건과 리포트 재검토 위치 1건 및 리포트 출처 2개가 로컬 보고서에 포함됐습니다. 모델 호출은 6턴이었습니다. 백엔드 조회와 저장은 이 검사에서 대체했으며 실제 업무 DB 저장과 화면 반영은 검사하지 않았습니다. 분석에는 정량 영향과 계약별 회수 여부에 관한 미확인 사항 및 출력 추가 검토 경고가 남았습니다.

2026년 10월 21일 회귀 테스트 36개가 10.16초에 통과했습니다. 관점의 S2와 S3 왕복, 체크포인트 재개, 정규화된 조회 공유, 원문 재사용, 중단된 조회의 예산 유지와 접근 범위 분리, 대기 및 토큰 제한, 문맥 처리 실패와 전체 시간 초과를 확인했습니다. 실제 Business MCP와 전용 PostgreSQL로 초기 단계에서 중단된 보고서의 재저장과 중복 저장 방지도 확인했습니다.

변경된 패키지를 저장소 밖에서 wheel로 빌드해 설치했고 두 실행 명령과 프롬프트 파일 포함을 확인했습니다. 설치된 패키지의 실제 연결 검사 1개가 41.23초에 통과했습니다. RabbitMQ 수신, 원본 백엔드 MCP, OpenDART, OpenAI 모델과 임베딩, pgvector 검색, 보고서 DB 저장을 확인했습니다. 메모 원문은 보존됐고 보고서는 한 건 저장됐습니다. 기존 백엔드 테스트 마커 경고 25개가 표시됐습니다. Ruff 검사와 형식 검사도 통과했습니다.

이번 변경에서는 재무 도구를 추가하고 학술 도구를 연결했습니다. AI 검사 41개와 External MCP 검사 59개를 통과했습니다. 실제 모델의 구조화 응답과 근거 및 투자 권유 판별 8개 사례를 확인했습니다. 실제 MCP 경로로 삼성전자 2025년 연결 재무 계정 229개와 학술 검색 요약 5개를 받았습니다. 이번 보고서 변경에서도 실제 큐부터 업무 DB 저장까지 34.40초에 통과했고 근거 없는 메모 제안이 비어 있음을 확인했습니다. 선택 이유의 실제 출력 검사도 별도로 확인했습니다. 사용자 화면의 버튼부터 보고서 표시까지의 검증과 다양한 실제 문장에 대한 투자 권유 판별 정확도 평가는 별도 범위입니다.

추가 보완 후 회귀 검사 47개가 10.41초에 통과했습니다. 실제 모델의 근거 및 투자 권유 판별 13개 사례도 통과했습니다. 실제 정정공시와 세 문장의 검증용 메모로 공시 등록, 큐 수신, MCP 조회, 분석과 보고서 저장을 연결한 검사는 24.99초에 통과했습니다. 정정표 10개 행, 기존 메모 세 문장에 대응하는 수정 제안 3건과 조건부 미래 영향 3건이 저장됐습니다. 재무 관점의 선택 이유와 확인된 분석도 포함됐고 원래 메모는 보존됐습니다. 근거 검사에서 제외된 일부 서술은 확인 범위에 표시했습니다. 사용자 실제 메모와 화면 전체 동작을 검증한 결과는 아닙니다.

## 8. 트러블 슈팅

긴 입력의 출처 목록을 절반씩 줄이면서 리포트 전체가 모델 입력에서 빠지는 문제가 있었습니다. 리포트를 참조하는 기본 분석과 research 분석에서는 문서 ID와 위치를 유지한 채 긴 본문을 줄이도록 보완했습니다. 실제 전송 JSON의 출처 위치가 모두 남는 회귀 검사로 확인했습니다. 표의 열을 모델이 이어 붙여 원문 문장이 달라지는 경우도 있어, 리포트 수정 대상은 모델이 위치를 선택하고 코드가 그 위치의 원문을 복원하도록 변경했습니다. 기본 분석에 보완 및 리포트 검토를 함께 요구할 때 해당 항목이 반복적으로 누락돼 별도 research 응답으로 분리했습니다.

이전 흐름에서는 관점 함수 내부에서 추가 조회까지 실행해 S3가 결과 취합만 담당했습니다. 관점 응답과 공유 조회를 분리하고 S3 결과를 받은 관점이 S2에서 재개하도록 연결했습니다. 조회 실행 상태를 메모리에만 보관하던 부분도 SQLite에 기록하도록 보완했습니다.

시간 초과를 일반 실패로 반환하면 보고서가 생성되지 않을 수 있었습니다. 공통 실행 함수가 체크포인트를 읽고 모델 호출 없이 비상 보고서를 보존하도록 수정했습니다. 이 경로의 SAVE_FAILED는 보고서가 로컬에 보존돼 재저장할 수 있다는 뜻입니다.

실제 공시의 정정표 전체를 출력 검사에 다시 포함하면서 검사 문장 수 한도를 넘는 문제가 있었습니다. 원문 정정표는 보고서 생성 근거로 전달하고 생성된 서술을 출력 검사 대상으로 유지하도록 수정했습니다. 초기 단계에 보존된 비상 보고서는 AI 저장 호출부가 백엔드의 허용된 단계 전환을 거쳐 저장하도록 보완했습니다.

사용자가 보존을 지시한 기존 build와 disclosure_ai.egg-info는 그대로 두었습니다. 실행과 패키지 설치의 기준 소스는 disclosure_ai입니다.

현재 백엔드 Compose에는 postgres 항목 중복이 있습니다. 원본은 수정하지 않고 검증용 PostgreSQL과 RabbitMQ를 별도로 실행했습니다. 재무 조회 도구 추가 외의 백엔드 기능과 프런트엔드는 수정하지 않았습니다.

근거 부족 상태의 서술이 보고서 모델에 전달되고, 빈 문자열이 메모 본문과 일치한 것으로 판정되는 문제가 있었습니다. 모델 입력 단계와 저장 직전 모두에서 해당 내용을 제외합니다. 긴 입력은 JSON 구조를 유지하며 줄이고 생략 여부를 모델에 알립니다. 출력 검사 문맥이 한도를 넘으면 전체 자유 서술을 제외합니다.

병합된 정정표에서 후속 행이 누락되고, 원문 줄바꿈 차이와 항목 번호를 문장 끝으로 처리한 탓에 유효한 제안이 빠졌습니다. 병합 열 복원, 문서와 위치에 따른 원문 복원, 번호를 보존하는 문장 분리를 적용했습니다. 모델 입력과 출력 검사에는 정정 전후 값을 별도로 전달합니다. 같은 원문을 반복해 입력 한도를 소진하는 문제는 출처 ID 참조로 줄였습니다.

## 시황 뉴스 관점

네 번째 시황 뉴스 관점과 매시간 수집 기능은 [시황 뉴스 안내](../docs/시황뉴스.md)를 따릅니다. 시황 관점은 저장된 제목만 분석하며 추가 검색과 재분석은 관점별 최대 3턴에 포함합니다. 시황 관점 입력은 최대 8,000토큰입니다. 실제 네이버 수집 및 AI 이용은 별도 허용 조건이 없어 비활성화했습니다.

### 회사 내부 리포트 RAG 연동

실제 `Tools`를 사용하는 실행은 `RAG MCP.search_research_reports(task_id, query)`로 내부 리포트를 조회합니다.
메모 기능과 분석 입력은 유지하며 사용자가 분석 시작 시 리포트를 첨부하지 않습니다.
조직·기업·공시 기준일·버전 범위는 Business API와 RAG MCP가 확정합니다. 로컬 JSON은 테스트용으로만 사용하며
MCP 오류 시 로컬 자료로 대체하지 않습니다. 기존 원문 검증·메모 보완 제안·리포트 수정 검토는 유지합니다.
리포트 초기 색인을 위해 해당 도구의 제한 시간은 전체 실행 예산 안에서 최대 60초입니다.
