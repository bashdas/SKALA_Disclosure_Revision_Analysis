### 목적
backend 아래 세 서비스와 공유 패키지의 최소 실행 구조를 구성합니다.

### 변경 내용
`backend/`에 Business API, Business MCP, RAG MCP, shared 패키지와 설정, Dockerfile, Compose, 환경변수 예제, 실행 문서, 테스트를 생성했습니다. 업무 모델·인증·큐 처리·업무 Tool·RAG 로직은 구현하지 않았습니다. 기존 파일의 이동·삭제 없이 본 기록만 추가했습니다. `.idea/`는 기존 미추적 변경으로 보존했습니다. 커밋과 원격 반영은 수행하지 않았습니다.

### 검증 결과
- Python 3.12 임시 가상환경에서 서비스별 pytest: API 1개, MCP 각각 2개, 총 5개 통과. RAG 테스트 Host 포트 수정 후 해당 2개 재검증 통과.
- `docker compose config --quiet` 통과, 세 이미지 빌드 성공.
- 별도 `disclosure-stage1-check` Compose 프로젝트에서 5개 컨테이너 모두 healthy 확인.
- Business MCP 컨테이너에서 세 서비스 내부 HTTP `/health` 응답의 status=ok 확인.
- 검증 컨테이너 종료, 데이터 볼륨 보존. 로컬 `backend/.env`는 예제에서 생성했으며 Git ignore 대상입니다.
- `git diff --check` 통과. 새 파일 공백 검사도 수행했습니다.

### 트러블슈팅
초기 uv 캐시와 Docker socket 접근이 sandbox에서 거부되어 승인된 권한으로 재실행했습니다. MCP 테스트에서 동일 manager 재시작 오류가 발생해 module 범위 client fixture로 수정했습니다. 테스트 수정 중 들여쓰기 오류는 바로 수정했습니다. Host 포트 없는 요청이 보안 allowlist에서 거부되어 실제 포트가 포함된 Host로 재검증했습니다. Starlette TestClient의 httpx 사용에 대한 deprecation warning은 남아 있으며 테스트는 통과했습니다.

### 남은 작업
SQLAlchemy/드라이버/Alembic 실행 환경, 실제 모델과 migration, JWT, 내부 인증, 업무 API와 MCP Tool, RabbitMQ 메시지 처리, RAG 검색 및 운영 설정은 다음 단계입니다. 의존성 lock 파일과 TestClient 경고 대응도 후속 작업입니다.

작성자: 박다솔
에이전트: Codex

관련 이슈와 PR: 미생성 (파일 수정과 테스트만 요청됨)

### 목적
PostgreSQL, SQLAlchemy, Alembic 기반만 구성하며 업무 테이블은 생성하지 않습니다.

### 변경 내용
SQLAlchemy 2.x sync + psycopg 3 및 Alembic 의존성을 추가했습니다. `app/core/database.py`에 Base, 지연 생성 Engine, session factory, 요청별 get_db를 구성했습니다. Service가 commit/rollback을 결정하고 dependency는 close로 미완료 트랜잭션을 정리합니다. `/health`는 유지하고 `/health/db`는 SELECT 1 및 실패 시 일반화된 503을 반환합니다. Alembic env.py, script template, versions 안내를 추가하고 Docker 이미지에 Alembic 파일을 포함했습니다. 기존 설정과 환경변수 예제를 확장했으며 업무 모델과 revision은 생성하지 않았습니다. 상세 파일 목록은 Git diff 및 새 파일에서 확인 가능합니다. backend README에 실행·테스트·모델 import 등록·schema 소유권 후속 결정을 기록했습니다.

### 검증 결과
- DB 없는 `python -m pytest -q`: 11 passed, 4 skipped (실제 PostgreSQL URL 미지정).
- 별도 임시 pgvector/pgvector:pg16 PostgreSQL에서 TEST_DATABASE_URL을 지정한 pytest: 최종 15 passed. config, Session 생성, 실제 SELECT 1, health, 연결 실패, 잘못된 자격 증명, 트랜잭션 정리, Alembic metadata 및 온라인 check 검증.
- `docker compose --project-directory backend -p disclosure-stage1-check build business-api`: 이미지 빌드 성공.
- 빌드 이미지에서 임시 PostgreSQL에 연결하여 `alembic check`: No new upgrade operations detected.
- `git diff --check` 통과. SQLite는 사용하지 않았습니다.
- 임시 PostgreSQL 컨테이너 종료 및 자동 제거. 기존 DB 및 볼륨은 변경하지 않았습니다.

### 트러블슈팅
uv 캐시 접근이 sandbox에서 거부되어 승인 후 재실행했습니다. 테스트 실패는 없었습니다. 기존 Starlette TestClient httpx deprecation warning 1개는 남아 있습니다. 작업 전부터 수정되어 있던 `.idea/workspace.xml`은 수정하지 않았습니다. Git 변경 명령, 스테이징, 커밋, 푸시는 실행하지 않았습니다.

### 남은 작업

## 2026.10.20 15:13 KST 핵심 도메인 ORM 및 Initial Migration

시작 시각: 2026.10.20 15:13 KST
종료 시각: 2026.10.20 15:21 KST
작성자: 박다솔
에이전트: Codex
상태: 완료
브랜치: server
관련 이슈와 PR: 미생성 (로컬 파일 수정과 검증만 요청됨)

### 목적
핵심 Enum, 업무 ORM, 관계와 제약조건 및 core schema initial migration을 구현합니다.

### 변경 내용
기존 sync Base/Engine/Session 설정을 유지했습니다. `app/models/enums.py`에 5개 StrEnum과 VARCHAR+CHECK 매핑을 추가하고, `common.py`와 `domain.py`에 UUID·timezone timestamp 기반 14개 업무 모델을 구현했습니다. 모든 FK는 RESTRICT이며 필요한 단방향 relationship에 passive_deletes=all을 설정했습니다. JSONB 3개 필드, Decimal/Numeric(24,4), 버전·순번 CHECK, 주요 unique/index를 추가했습니다. Approval은 작업별 1개, Filing 접수번호는 조직별 unique, thread_id는 전역 unique입니다. PENDING 승인자/시각 및 수정문 없는 제안의 after_text는 nullable입니다.

Alembic initial revision `0001_initial_core`를 생성·검토하고 core schema 생성/삭제를 명시했습니다. env.py는 core schema만 비교하도록 확장했고 RAG/checkpoint/public의 다른 테이블은 제외합니다. public.alembic_version은 기존 설정과 호환되게 유지합니다. 신규/수정 파일은 Business API README, models 4개 파일(기존 __init__ 포함), migration/env/안내, PostgreSQL 모델/migration 테스트, 기존 DB 테스트, backend README 및 본 기록입니다. 상태 전이·Service·Repository·API·인증·Queue·MCP·RAG 코드는 구현하지 않았습니다.

### 검증 결과
- mapper 구성 및 기존 metadata의 14개 테이블 등록 확인.
- DB 미설정 최초 pytest: 12 passed, 24 skipped (실제 DB 테스트 skip). 이후 FK/NOT NULL 통합 테스트 1개를 추가했습니다.
- 최초 PostgreSQL 전체 테스트: 35 passed, 1 failed. 원인은 아래 테스트 입력 길이 문제였으며 수정했습니다.
- 임시 PostgreSQL(pgvector/pgvector:pg16)에 TEST_DATABASE_URL 및 TEST_ALLOW_SCHEMA_RESET=1을 지정한 최종 pytest: 37 passed, warning 1개.
- 생성·관계, email/버전/thread/approval/event/application unique, 양수 CHECK, Decimal 최대 자리수 roundtrip, JSONB, timezone timestamp, FK/NOT NULL, raw SQL Enum CHECK, loaded-parent 삭제 차단과 audit 보존 검증.
- migration upgrade → downgrade base → 재-upgrade 성공. 14개 테이블 및 index/FK/CHECK 확인, native enum 없음 확인, Alembic check 성공. 다른 schema/public의 probe 테이블이 downgrade 동안 보존됨을 검증했습니다.
- SQLite와 create_all은 사용하지 않았습니다. Git diff 및 신규 파일 공백 검사 통과. 임시 DB 컨테이너를 종료·자동 제거했습니다.

### 트러블슈팅
Enum CHECK 테스트에 길이가 긴 invalid 값을 넣어 VARCHAR 길이 제한이 먼저 발생했습니다(DataError). 짧은 BAD 값으로 수정해 DB CHECK 위반을 직접 검증했고 재실행에서 전체 통과했습니다. 기존 TestClient httpx deprecation warning 1개는 그대로입니다. 작업 전부터 변경된 .idea/workspace.xml은 보존했습니다. 금지된 Git 변경 명령은 실행하지 않았으며 커밋/원격 반영은 없습니다.

### 남은 작업
다음 작업은 AnalysisTask 상태 머신 + 핵심 Repository입니다. 조직 간 참조 일치, 승인/제안/적용 기록의 같은 작업 여부, 메모 current/base/result 버전 실재 여부는 개별 FK만으로 보장하지 않으므로 향후 Service에서 검증해야 합니다. 이메일 정규화, 승인 상태별 필수값, 금액/통화 정책은 후속 업무 규칙입니다. 기존 core schema가 있는 실제 DB는 initial migration 적용 전에 충돌을 검토해야 합니다.
