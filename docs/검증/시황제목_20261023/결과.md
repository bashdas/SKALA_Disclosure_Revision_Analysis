# 제목 기반 시황 기능 검증 결과

## 완료 범위와 미확인 범위

첨부한 요구사항에 맞춰 공식 API 연결, 최소 적재 후 분류와 재처리, 보존 정책 및 제목 기반 시황 분석을 구현하고 로컬 컨테이너에 반영했습니다. 실제 네이버 수집 및 AI 이용은 비활성 상태입니다. 사용자는 별도 이용 허용 조건이 없다고 확인했고, 현재 환경에 네이버 API 키도 없었습니다. 공개 약관에서 해당 AI 이용과 저장을 제한하므로 실제 네이버 연결 검증을 완료했다고 보고하지 않습니다. HTML이나 기사 본문 수집으로 우회하지 않았습니다. 조건과 설정은 [운영 안내](../../시황뉴스.md)에 정리했습니다.

실제 모델 검증에는 직접 만든 합성 제목만 사용했습니다. 이 결과는 실제 네이버 검색 품질, 기업별 기사 포괄성, 한 시간 후 자동 수집 성공이나 장기간 정확도를 입증하지 않습니다. 사용자 기존 메모와 과거 보고서를 덮어쓰지 않았습니다.

## 최종 구성

External MCP의 공식 뉴스 API, RAG MCP의 시간별 수집과 분류, 같은 PostgreSQL rag 스키마 및 별도 뉴스 도구를 연결했습니다. 기본 분석과 기존 세 전문 관점 및 보고서 역할은 유지했고 네 번째 MARKET_NEWS는 제목에 나타난 시황 사건과 기존 가정의 연결을 검토합니다. 관점 선택은 기본 모델이 판단합니다. 기존 Core와 화면에 네 관점 타입이 이미 반영된 것을 확인해 같은 정의를 재사용했습니다.

수집 페이지를 PENDING으로 먼저 저장하고 분류를 후속 수행합니다. 모델 실패 후에도 기사와 검색 범위가 남는 것이 적재 전 일괄 분류와의 차이입니다. 분류는 제한된 병렬 배치로 실행하고 재시도와 예산 한도를 적용합니다. 짧은 별칭과 계열사 접두사만으로는 직접 기업 연결을 확정하지 않습니다. 모델은 제공된 후보 코드만 선택할 수 있으며 불명확한 항목은 UNRESOLVED로 보존합니다.

신규 DB와 서비스는 추가하지 않았습니다. 기존 백그라운드 수명주기와 DB 잠금을 재사용했습니다. 사용자 분석 RabbitMQ 작업과 뉴스 수집의 시간 및 모델 예산은 분리했습니다. 보고서 중복 설명은 역할별 프롬프트로 줄이고 동일한 도구 요청은 기존 공유 조회 캐시를 사용합니다.

## 실제 모델과 전용 DB 검증

live_synthetic.py는 합성 제목 네 개의 실제 분류와 두 번의 실제 시황 관점 응답을 저장했습니다. 복수 기업의 협력, 모호한 별칭, 금리와 조선업 공급망을 입력했습니다. 초기 분류에서 짧은 별칭을 특정 기업으로 확정한 사례가 있었습니다. 이 응답을 live-synthetic-result.json에 보존하고 기업명 경계와 추가 식별 근거를 확인하는 보완을 적용했습니다.

live_pipeline.py는 합성 공식 검색 응답을 사용하면서 실제 OpenAI 분류와 PostgreSQL 적재, 실제 RAG 서비스 검색을 연결했습니다. 네 제목이 먼저 저장됐고 최종 범위는 COMPANY 1개, MACRO 1개, INDUSTRY 1개, UNRESOLVED 1개였습니다. 기존 기업과 공통 및 연결 산업 검색에서 세 제목을 반환했고 미확정은 제외됐습니다. 네이버 API와 기사 링크에는 접속하지 않았습니다. 모델 원래 응답과 최종 적재 상태를 live-pipeline-result.json에 구분했습니다.

두 실제 시황 응답은 COMPLETED였습니다. 금리 제목에서는 금융비용의 정량 변화를 확정하지 않고 차입 구조와 민감도를 확인할 질문을 제시했습니다. 일정 안내 제목에서는 금리나 금융비용 변화를 확인할 수 없다고 설명하고 후속 자료 확인 질문을 남겼습니다. 이 상태는 확인한 범위의 부분 분석 완료이며, 금융비용이 달라졌다는 판정으로 해석하지 않습니다. 전체 사용자 API 보고서 생성 반복 실험은 수행하지 않았습니다.

## 실패 기록과 수정

기존 본문 조회를 전제로 한 테스트를 제목 계약으로 전환했습니다. 최초 AI 재검사에서는 추가 뉴스 검색의 as_of=None을 공통 인자 정규화에 넣어 ValueError가 발생했습니다. 선택적 값이 없으면 해당 인자를 생략하도록 고쳤고 전체 회귀 검사가 통과했습니다.

일부 테스트 문서에 URL이 없어 최종 출처 링크가 비는 실패가 있었고, 실제 RAG 응답과 같은 제목 메타데이터를 가진 fixture로 보완했습니다. 새 예산 테스트는 실행 이벤트의 필드명을 event로 잘못 읽어 실패했고 실제 필드 kind로 고쳤습니다. 본문 기반 기존 리포트 통합 검사는 제목의 documents와 sources 계약으로 갱신해 회귀를 확인했습니다.

별칭의 과도한 확정은 실제 모델에서 발견했고 최종 파이프라인에서 미확정으로 보존되는 것을 확인했습니다. 기업 분류의 일반적인 정확도와 모든 동음이의어에 대한 보장은 하지 않습니다. 스키마를 지킨 응답도 의미가 틀릴 수 있으며 주관적 confidence를 확률로 사용하지 않습니다.

## 운영 반영

RAG 0003_news_pipeline을 운영 DB에 적용하고 External MCP, RAG MCP와 AI Worker를 다시 빌드했습니다. 뉴스 데이터의 이용 상태를 변경한 환경값을 제외하고 기존 연결과 인증 환경, AI 상태 볼륨을 보존했습니다. 실제 수집은 꺼져 있고 뉴스 반환은 NEWS_USAGE_NOT_AUTHORIZED, 공식 검색은 호출 0회, 본문 도구는 NEWS_BODY_DISABLED를 반환하는 실제 MCP 점검을 수행했습니다. 공시 분석의 기존 서비스는 계속 실행 중입니다.

재배포 후 기존 메모 버전 25개와 보고서 31건을 확인했습니다. 기존 뉴스 목록 182건은 LEGACY로 보존됐고 새 분류 검색에서 제외됩니다. 삭제 미리보기는 삭제 예정 0개, 남은 행 182개와 논리 크기 1,231,680바이트였습니다. 수집이 꺼져도 만료 유지 작업은 실행됩니다. 최종 컨테이너 소스 대조는 runtime-check.json에 기록합니다.

일반 7일과 중요 30일, 미확정 48시간 및 실행 로그 14일은 별도 허용 조건이 있는 데이터에 적용하는 기본 정책입니다. 활성 기사 50,000행과 논리 크기 128 MiB를 상한으로 관리합니다. 물리 DB 파일 및 색인과 WAL 용량은 별도 운영 감시 범위입니다. 원문 제목, 태그와 벡터는 같은 행에서 정리하고 보고서 인용 당시 스냅샷은 분리해 보존합니다. 실제 데이터 스냅샷 보존도 이용 조건 확인이 필요합니다.
