# 시황 뉴스 구현 검증

2026년 10월 23일 로컬 disclosure-web 서비스에 반영했습니다. 작업 브랜치는 feat/24-market-news-runtime이며 같은 기능을 원래 작업 폴더의 feat/24-market-news-analysis에도 통합했습니다. 동시에 진행 중인 리포트 기능 변경을 보존했습니다. main 커밋, 병합과 원격 푸시는 수행하지 않았습니다. 관련 이슈는 https://github.com/bashdas/SKALA_Disclosure_Revision_Analysis/issues/24 입니다.

## 구현과 자동 검증

| 요구사항 | 구현과 확인 |
| --- | --- |
| 네이버 뉴스만 수집 | 네이버 검색과 경제, 세계 목록에서 네이버 기사 링크만 수집합니다. 호스트와 경로, 리다이렉트 검증 테스트를 수행했습니다. |
| 즐겨찾기와 공통 시황 | 활성 사용자의 즐겨찾기 기업을 합치고 공통 목록을 조회합니다. 실제 운영 첫 수집에서 기업 7개를 조회했습니다. |
| 저장 전 모델 기업 분류 | gpt-5.4-mini 구조화 응답으로 기업 태그와 공통 여부를 판정한 뒤 제목 임베딩과 함께 저장했습니다. |
| 제목과 링크만 수집 | market_news에 기사 본문 열이 없음을 DB 테스트로 확인했습니다. |
| 매시간 실행과 만료 삭제 | DB 시작 시각, 중복 실행 잠금과 30일 만료 삭제를 실제 PostgreSQL 테스트로 확인했습니다. 59분 후 생략과 60분 후 실행은 고정 시각 테스트입니다. 실제 한 시간 후 두 번째 수집은 아직 관찰하지 않았습니다. |
| 네 번째 관점과 RAG MCP | NEW와 CORRECTION의 네 관점, 조회와 재분석, 기사 출처 보고서를 모의 모델로 검증했습니다. 실제 모델과 MCP로 기사 본문 및 보고서 출처 연결도 확인했습니다. |
| 모델의 관점 선택 | 기본 모델의 선택과 미선택을 유지했습니다. 관련 기사 없음으로 보류하는 검사도 통과했습니다. |

AI 전체 테스트 90개가 통과했고 실제 외부 실행 조건이 필요한 2개는 건너뛰었습니다. External MCP 95개가 통과했습니다. RAG MCP의 모델 모의 및 DB 통합 테스트는 6개입니다. Business API 577개 통과와 19개 건너뜀을 확인했고 별도 마이그레이션 검사 17개가 통과했습니다. 프런트엔드 82개와 타입 검사 및 빌드가 통과했습니다.

RAG DB 재검사 첫 실행은 별도 실제 수집 검증이 남긴 101개 행 때문에 예상 집합 비교에 실패했습니다. 전용 검증 DB의 테스트 정리 후 같은 검사로 재확인했습니다. 운영 DB를 초기화하지 않았습니다. 첫 재검사에서 PYTHONPATH를 빠뜨린 수집 오류도 있었고 backend/shared를 지정해 다시 실행했습니다.

## 실제 수집

운영 첫 수집은 10시 22분에 시작해 10시 23분에 끝났습니다. 중복 제거한 제목과 링크 101개가 저장됐고 모델은 43개를 공통 시황으로 분류했습니다. 삼성중공업 3개, SK하이닉스 3개 등 기업별 검색도 수행했습니다. 코아스, 미로바펀즈, CENTENE CORP 검색에서는 네이버 기사 링크가 없어 NAVER_HEADLINES_EMPTY를 기록했습니다. 전체 결과는 COMPLETED_WITH_WARNINGS입니다. 결과가 없는 기업의 기사는 생성하지 않았습니다.

별도 검증 DB의 실제 수집 결과는 live-collection.json과 live-classifications.json에 있습니다. 이 실행도 101개를 저장했고 공통 태그는 47개였습니다. 운영 첫 수집의 43개와 구분합니다. 제목에 대한 모델 분류는 실행별로 달라질 수 있습니다.

마지막 재생은 실제 모델과 실제 네트워크를 사용했습니다. 기존 작업의 입력과 시황 선택을 고정해 해당 관점부터 실행한 진단이며 새 전체 API 작업 저장과 구분합니다. 완료된 기존 보고서를 수정하지 않았습니다. 기사 선택 모델과 본문 분석 모델, 보고서 모델의 입출력 및 실제 도구 응답은 market-agent-replay.json에 보존했습니다. 보고서는 market-agent-report.md입니다. 연결된 네이버 기사는 https://n.news.naver.com/mnews/article/421/0009245727 이며 원문 검증 후 news 문서 ID로 인용됐습니다.

본문 누락의 원인은 시황 모델이 공시만으로 답하고 추가 조회를 생략할 수 있던 흐름이었습니다. 시황 관점이 선택되면 기사 선택 계획을 모델에게 먼저 묻는 단계로 바꿨습니다. 모델이 관련 기사 ID 또는 추가 검색어와 이유를 고릅니다. 코드의 키워드 규칙으로 관점이나 기사를 선택하지 않습니다. 관련 자료가 없으면 보류할 수 있습니다.

## 반영과 한계

Core와 RAG의 추가 마이그레이션을 적용했고 Business API, External MCP, RAG MCP와 AI Worker 이미지를 다시 빌드했습니다. 기존 인증 설정과 worker 상태 볼륨을 보존했습니다. RAG MCP의 매시간 수집기는 실행 중이며 프런트엔드 소스에는 네 번째 관점 카드가 반영됐습니다.

제목 분류만으로 모든 관련 기업을 정확히 찾는 것을 보장하지 않습니다. 네이버 검색 첫 응답에 없는 기사는 수집하지 못할 수 있습니다. 발행일을 모르는 수집 항목은 최초 수집일부터 30일로 만료를 계산하고 실제 분석 시 본문의 발행 및 수정 시각을 검사합니다. 기사 본문 조회 실패와 관련 자료 없음은 보고서 제한에 남깁니다. 전체 API 분석에서 시황 관점이 반드시 선택되는 것으로 보고하지 않습니다.

인증 정보는 결과물에서 제외했습니다. 실행 테스트의 계정 인증값과 환경 파일은 저장소 밖 또는 Git 제외 경로에만 보존했습니다. 기존 메모와 이전 보고서 및 다른 작업자의 변경을 보존했고 제출, 작업, 산출물 폴더를 생성하지 않았습니다.

최종 반영 후 코드와 프롬프트 59개 파일의 실행 컨테이너 해시가 격리 검증 소스와 일치했습니다. runtime-check.json에 확인 목록과 수집 상태를 보존했습니다. live_analysis_fifth.py는 실행하지 않은 진단 후보이며 실제 실행 횟수에 포함하지 않았습니다.
