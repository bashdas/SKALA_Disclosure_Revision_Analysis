## 관점 응답과 출처 검증

두 관점의 최초 저장 결과는 findings="", sources=[], requests=[]입니다. INDUSTRY_CONTRACT의 limitations에는 "취소된 1척의 제3자 매각이 실제로 진행되었는지, 잔존 1척의 인도와 잔금 회수가 완료되었는지는 확인되지 않았습니다."가 남았습니다. FINANCE에는 "기수취 선수금이 이미 받은 금액인지, 향후 제3자 매각대금이 새로 유입될 금액인지 구분할 수 있는 근거가 현재 자료에 부족합니다."가 남았습니다. 전체 문장은 체크포인트와 업무 DB 사본에 있습니다.

finish_perspective는 COMPLETED 이외의 결과에서 findings와 sources, requests를 비운 뒤 저장합니다. 따라서 비우기 전 문장과 연결 출처는 현재 로그에서 복구할 수 없습니다. 위 limitations는 삭제된 findings의 원문으로 간주하지 않았습니다.

validated_sources는 document_id, location, quote를 원문과 대조합니다. 불일치 항목은 반환에서 빠지며 탈락 이유를 남기지 않습니다. 코드 위치는 services/documents.py 352~403행입니다. 관점에서 검증 후 출처가 하나도 없으면 "검증 가능한 출처가 없습니다."를 추가하고 상태를 바꿉니다. 두 관점에는 이 문구가 없습니다. 모델이 처음부터 근거 부족으로 답했을 가능성을 뒷받침하는 정황입니다. 최초 응답과 검증 전후 출처가 없어 확정은 보류합니다.

두 관점은 context_truncated=true를 limitations에 언급했습니다. runtime.py의 입력 축소 경로와 일치하는 정황이지만, 축소 후 실제 전송 JSON이 기록되지 않아 어떤 원문이 빠졌는지는 확인하지 못했습니다. 선수금 관련 문장이 실제 모델 입력에도 있었는지, 있었지만 모델이 놓쳤는지는 구분할 수 없습니다.

## 출력 검사와 최종 상태

보고서 입력에서 COMPLETED인 관점의 출처나 본문이 없으면 reporting.py 88~98행에서 근거 부족으로 바꿀 수 있습니다. 검사 후 본문이 빈 경우에는 212~214행에서도 바꿀 수 있습니다. 이번 두 관점은 이 분기들에 도달하기 전에 이미 같은 상태였습니다. 화면의 "근거 부족으로 미작성"은 reporting.py 18행의 상태 표시입니다. 관점 모델의 보류와 출처 연결 실패를 화면 문구만으로 구분할 수 없는 구조입니다.

검사 모델의 의미상 근거 부족 판단, 안전성 정책 제외, 실행 한도 초과를 이번 상태의 원인으로 각각 확정하지 않았습니다. 출력 검사 한도 초과와 오류를 나타내는 기록은 없고 관점 상태도 LIMIT_REACHED나 FAILED가 아닙니다. 안전성 제외와 의미상 근거 판단의 개별 결과는 미기록입니다.
