# 시황 뉴스 수집과 보고서 분석

즐겨찾기한 기업 전체를 대상으로 네이버 뉴스 제목과 링크를 매시간 수집합니다. 경제와 세계 뉴스 목록에서는 여러 기업에 영향을 줄 공통 시황을 찾습니다. RAG MCP가 시작될 때 첫 작업을 수행하고, DB에 기록한 시작 시각을 기준으로 3,600초가 지나면 다음 작업을 실행합니다. 여러 인스턴스가 같은 DB에 연결되면 PostgreSQL 잠금으로 중복 수집을 막습니다.

수집 에이전트는 제목을 모델에 전달해 관련 기업명, 확인 가능한 기업코드, 공통 시황 여부와 분류 이유를 붙입니다. 특정 키워드에 따른 기업 분류 규칙은 사용하지 않습니다. 모델 분류가 실패한 배치는 저장하지 않고 수집 기록에 실패를 남깁니다. 같은 링크는 중복 삽입하지 않습니다. 모델 또는 즐겨찾기 목록이 바뀌면 태그를 다시 검토합니다.

수집 목록은 30일간 보관합니다. 시황의 최근성을 유지하면서 월간 흐름을 비교할 수 있는 기간으로 정했습니다. 본문을 가져오지 않은 수집 목록에는 발행 시각이 없을 수 있어 최초 수집 시각으로 보관 기간을 계산합니다. 다음 정기 수집 시 만료된 목록을 삭제합니다. 과거 분석 보고서와 검증 근거는 보존합니다.

## 네 번째 관점

공통 LangGraph 흐름에 MARKET_NEWS(시황 뉴스)를 추가했습니다. 신규공시와 정정공시 모두 기존 메모 검색과 같은 분석 흐름을 사용합니다. 기본 분석 모델이 공시와 메모, 저장된 뉴스 목록을 보고 관점 선택 여부와 이유를 판단합니다. 최대 네 관점을 실행할 수 있으며 매번 네 관점을 강제하지 않습니다.

시황 관점이 선택되면 모델이 저장된 실제 기사 ID를 최대 세 개 고르거나 추가 검색어를 작성합니다. search_market_news는 RAG MCP의 제목 임베딩 검색을 사용합니다. read_market_news는 작업의 기업 또는 공통 시황으로 분류된 기사 ID를 확인한 뒤 External MCP를 통해 네이버 링크의 본문을 읽습니다. 기사 목록에 본문은 저장하지 않습니다. 분석에 실제 사용한 본문은 기존 분석 근거 보존 절차에 따라 체크포인트와 보고서 출처에 남습니다.

제목과 태그는 기사 선택용 자료입니다. 본문 분석에서는 확인된 사실, 보도 또는 회사 전망, AI의 조건부 해석을 구분하도록 지시했습니다. 본문을 조회하지 못하면 실패 이유를 남깁니다. 검증된 기사 출처를 보고서에 연결하며 기존 메모는 보존합니다.

뉴스 조회 기준은 분석 요청 생성 시각입니다. 그 시각 이후에 수집되거나 발행 또는 수정된 기사는 해당 작업의 근거에서 제외합니다. 시황을 사용하는 보고서에는 이 기준 시각을 표시합니다. 공시 기준일 당시 시황을 복원하는 기능은 포함하지 않았습니다.

## 실행 설정과 위치

backend/.env의 NEWS_COLLECTION_ENABLED=true, NEWS_COLLECTION_INTERVAL_SECONDS=3600, NEWS_RETENTION_DAYS=30, NEWS_CLASSIFICATION_MODEL=gpt-5.4-mini를 사용합니다. 분류와 제목 임베딩에는 기존 RAG MCP의 OPENAI_API_KEY가 필요합니다. 스케줄러는 RAG MCP의 수명주기에 연결되어 별도 호스트 cron이 필요하지 않습니다. 컨테이너가 중단된 시간에는 수집하지 않으며 재시작할 때 누락된 여러 회차를 한꺼번에 실행하지 않습니다.

핵심 파일은 backend/mcp/external-mcp/app/naver_news.py, backend/mcp/rag-mcp/app/news_collector.py와 news_store.py, ai/disclosure_ai/workflow/perspectives.py, prompts/news_plan.md입니다. DB 마이그레이션은 Core 0010_market_news_perspective와 RAG 0002_market_news입니다. 프런트엔드 관점 카드와 타입에도 시황 뉴스를 추가했습니다.

전체 모델 예산은 80,000 예약 토큰과 12턴, 보고서 전 분석은 64,000 토큰과 10턴입니다. 전체 시간 120초와 보고서 시간 30초는 유지했습니다. 시황 기사 선택과 본문 분석은 같은 관점의 최대 3회 모델 호출에 포함됩니다. 인증, 취소, 출처 검증과 조회 재시도 통제는 유지했습니다.

검증과 실제 실행의 한계는 [검증 기록](검증/시황뉴스_20261023/결과.md)에 정리했습니다.
